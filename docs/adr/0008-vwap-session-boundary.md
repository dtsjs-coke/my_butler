# ADR-0008: VWAP 세션 경계 — 자정 리셋 제거, 미국장 리셋 시각 서머타임 자동 전환, 세션 전체 봉 사용

- **날짜**: 2026-10-07 (최초 작성 2026-10-06)
- **상태**: **Accepted** — 구현·테스트 완료, 커밋 `a72d12d`로 S9 배포 완료(상태 갱신 2026-10-07). 사용자 결정("세션 경계 수정을 먼저 마무리")에 따른 작업이다. 2026-10-07 사용자가 F1b(세션 전체 봉 사용, D3) 유지를 결정했다.

- **선행 문서**: [ADR-0007](0007-vwap-shadow-replay-strategy-plugin.md)의 F1·F2, [`docs/vwap_stage3_design.md`](../vwap_stage3_design.md) §8
- **관련 파일**: `core/vwap/session.py`(신규), `core/vwap/strategy.py`(`calculate_vwap`만), `core/vwap/bot.py`, `core/vwap/broker.py`(`TossBroker.get_candles`), `core/vwap/backtester.py`(1줄), `scripts/test_vwap_session.py`(신규)

## 배경 / 문제

3단계 설계 중 기존 버그 두 개를 발견했다(설계 문서 §8).

- **F1 — KST 자정에 VWAP이 리셋된다.** `calculate_vwap`은 "봉의 달력 날짜가 바뀌면 새 세션"으로 처리했다. 미국장은 22:30~05:00 KST(서머타임)이므로 장 도중 00:00에 VWAP·매수/매도 타겟·Dev Band 표준편차가 처음부터 다시 계산됐다. 재현: 23:59 종가 100 → 00:00 종가 106(거래량 같음)에서 기대 VWAP 103.0, 실제 106.0.
- **F2 — 리셋 시각 22:30 고정.** 미국 서머타임은 **2026-11-01(일)** 에 끝난다. 그 뒤 정규장 개장은 23:30 KST다. 22:30 고정이면 프리마켓 한가운데에서 새 세션이 시작된다. 운영 설정 5개(`real/virtual/virtual_1~3_reset_time`)가 모두 22:30이다.

이번 리뷰에서 하나를 더 확인했다.

- **F1b — 봇은 항상 최근 150봉만 받았다.** `bot.py`가 `get_candles(ticker, interval, 150)`을 호출했으므로 1분봉 기준 VWAP 누적 구간은 최대 2.5시간이었다. 실제로 운영된 VWAP은 "리셋 시각, 자정, 150봉 전" 중 **가장 늦은 시점부터의 누적값**이다. 대시보드 설명("당일 리셋 시각부터 누적")과 다르다. F1만 고치고 150봉을 그대로 두면 바뀌는 구간은 00:00~01:00 정도뿐이다.

중단된 이전 작업(10/5 23:52, 미기록·미검증·S9 미반영)도 리뷰했다. 그 작업은 미국 종목에 "뉴욕 정규장 09:30~16:00만 VWAP에 누적하고 **정규장 밖에서는 신규 매수 금지**" 규칙을 넣었다. 그런데 실거래 기록(`vwap_trades_real.json`)을 보면 체결의 상당수가 정규장 밖에서 났다(13:44, 15:38 주간거래, 21:29 프리마켓, 06:49·08:50 애프터마켓 등). 그 규칙은 F1/F2 수정 범위를 넘는 큰 매매 규칙 변경이다. 회귀 테스트도 63/69, 47/57로 깨져 있었다. 그 밖의 문제도 있었다. 설정 키 `{mode}_session_mode`는 `config_manager.load_config`가 기본값에 없는 키를 버리기 때문에 동작하지 않았다. 토스 캔들 페이징(`before`/`nextBefore`)은 확인되지 않은 가정이었다(설계 문서 F6). 그런데도 페이징이 실패하면 매수를 영구 보류하도록 연결돼 있었다.

## 결정

### D1. 세션은 "리셋 시각 ~ 다음 리셋 시각"으로만 나눈다. 자정으로는 끊지 않는다.
`core/vwap/session.py`의 `SessionSpec` 하나가 세션 경계를 정한다. `calculate_vwap`·일 손실한도 세션 날짜·거래 시작 시각 대기·요청 봉 수가 모두 이것을 쓴다. 세션 날짜(`session_key`) 형식은 기존 `get_session_date`와 같은 `YYYY-MM-DD`(세션 시작일)다.

### D2. 미국 종목이고 `reset_time`이 22:30 또는 23:30이면 서머타임에 따라 자동 전환한다(US_AUTO).
- 리셋 시각은 그날 뉴욕 09:30 개장 시각을 KST로 바꾼 값이다. 서머타임이면 22:30, 아니면 23:30이다. 판정은 미국 규칙(3월 둘째 일요일~11월 첫째 일요일)을 **직접 계산**한다. S9(Termux)에 tzdata가 있는지에 의존하지 않기 위해서다. 테스트에서 2026~2030년 전 날짜를 `zoneinfo`와 교차검증했다.
- 다른 값(예: 21:00)을 넣은 경우와 국내 종목은 그 값을 **그대로 고정**해서 쓴다(RESET_TIME). 사용자가 일부러 정한 시각은 바꾸지 않는다.
- **새 설정 키는 없다.** 운영 설정이 모두 22:30이므로 배포만 하면 자동 전환이 적용된다. UI 변경도 필요 없다.
- 정규장 밖 봉(프리·애프터·주간거래)은 **지금처럼 VWAP에 누적**한다. 정규장 밖 매수 금지 같은 매매 규칙은 넣지 않는다. 바뀌는 것은 "세션이 언제 시작하나"뿐이다.

### D3. 봇은 세션 시작부터의 봉을 받는다(최소 150, 최대 1600).
`bars_needed = (지금 - 세션 시작) / 봉 간격 + 30`이고 최소 150, 최대 1600이다. 200봉을 넘으면 `TossBroker.get_candles`가 `before`/`nextBefore` 페이징을 **시도**한다. 이 API 형태는 확인되지 않았으므로 실패해도 안전하게 동작하도록 만들었다.
- `nextBefore`가 없으면 첫 페이지(최대 200봉)만 쓴다. 예전 150봉과 비슷한 부분 VWAP이 된다.
- `before`가 무시돼 더 과거 봉이 오지 않으면 즉시 중단한다.
- 2페이지 이후 HTTP 오류나 예외가 나면 받은 만큼만 쓴다. 예전 코드였다면 받은 봉을 버리고 Yahoo로 폴백했다.
- 첫 페이지 실패는 기존처럼 Yahoo로 폴백한다.
- 세션 시작부터의 봉을 다 받지 못하면 **경고 로그(세션당 1회)와 status `vwap_full_session=false`만 남긴다.** 매매는 막지 않는다. 이 경우의 동작은 기존(부분 VWAP)과 같다.

### D4. 시각은 KST naive로 통일한다. 오프셋이 있는 timestamp는 KST로 변환한다.
`to_kst_naive`가 처리한다. tz 정보가 있으면(`+09:00`, `Z` 등) KST로 변환하고, 없으면 KST로 간주한다(Yahoo 경로와 기존 코드의 가정과 같음). `TossBroker`는 프로세스당 1회 첫 캔들 응답의 **원본 timestamp 문자열**, 서버 현재시각, `nextBefore` 유무를 INFO 로그로 남긴다. 배포 후 이 로그 한 줄로 아래 가정 A1·A2를 확정한다.

### D5. 서머타임 종료 후 "거래 시작 시각" 보정 (US_AUTO에만 적용)
시작 시각이 새 개장 시각보다 **최대 1시간 앞**이 되면 대기 없음으로 처리한다(예: 시작 23:00, 표준시 개장 23:30). 기존 규칙대로라면 다음 날 23:00까지 약 24시간을 기다리게 된다. 다른 경우는 기존 규칙을 그대로 따른다.

## 확인하지 못한 가정

- **A1. 토스 캔들 timestamp의 시간대.** 직접 확인하지 못했다. S9에서 읽기 전용 API를 호출하려 했으나 권한 정책으로 막혔다. 간접 근거는 이렇다. 코드 주석과 테스트 픽스처를 보면 토스 주문 API의 시각은 `2026-10-05T23:31:15.000+09:00` 형식(ISO 8601, +09:00)이다. 캔들도 같은 형식일 가능성이 높다.
  - 오프셋이 있는 경우(+09:00이든 Z든): 새 코드는 정확히 KST로 변환하므로 **결과가 옳다**. 참고로 기존 코드에서 timestamp가 `Z`(UTC)였다면 날짜 경계는 09:00 KST, 리셋 22:30은 07:30 KST로 해석됐을 것이다. F1의 증상이 "자정 리셋"이 아니라 그쪽으로 나타났을 것이다.
  - **오프셋이 없고 실제로는 UTC인 경우**(가능성 낮음): 모든 봉이 9시간 어긋난다. 세션 경계가 실제 07:30/08:30 KST가 되어 VWAP이 미국장 도중에 끊긴다. 기존 코드에도 같은 문제가 있었으므로 새로 생기는 위험은 아니다. 다만 위 1회 로그로 반드시 확인해야 한다.
- **A2. 토스 캔들 페이징(`before`/`nextBefore`).** 확인하지 못했다. 지원되지 않으면 D3에 따라 최대 200봉으로 동작한다(예전과 비슷). 이 경우 F1·F2 수정의 효과는 세션 시작 후 약 3시간 동안만 나타난다.

## 근거

- 실거래가 정규장 밖에서 많이 체결되므로, 정규장 필터나 매수 금지는 "버그 수정"이 아니라 전략 변경이다. 전략 변경은 4단계(ADR-0009)에서 백테스트와 함께 판단할 일이다.
- reset_time 값(22:30/23:30)으로 자동 여부를 정하는 방식을 택한 이유는 이렇다. 새 설정 키·UI·마이그레이션이 필요 없고, 운영 설정 전부가 별도 조치 없이 11/1 이후에도 맞게 동작한다. 사용자가 다른 시각을 넣었다면 그 의도를 존중한다.
- 세션 전체 봉(D3) 없이는 F1 수정이 거의 의미가 없다(F1b). 대시보드·가이드가 설명하는 "리셋 시각부터 누적"도 D3가 있어야 실제로 지켜진다.

## 결과

### 좋아지는 것
- 미국장 도중 00:00에 VWAP·타겟·Dev Band가 리셋되지 않는다.
- 2026-11-01 이후 세션이 23:30(정규장 개장)에 시작한다. 사용자가 설정을 바꿀 필요가 없고, 2027-03-14 서머타임 시작 때도 자동으로 22:30으로 돌아간다.
- VWAP이 설명대로 "세션 시작부터의 누적"이 된다(페이징이 지원되는 경우).
- 일 손실한도 세션 날짜와 거래 시작 시각 대기가 VWAP과 같은 세션 기준을 쓴다.

### 감수하는 것 (운영 체감 변화)
- **VWAP이 지금보다 훨씬 느리게 움직인다.** 예전에는 최근 약 2.5시간 누적이었고, 이제는 세션 전체 누적이다. 특히 주간거래·애프터마켓 시간대의 VWAP은 정규장 거래량이 크게 반영되어, 예전보다 정규장 가격 쪽에 붙어 있게 된다. 같은 N%/M% 설정이라도 매수/매도 타겟 위치와 체결 빈도가 달라질 수 있다. Dev Band 표준편차도 세션 전체 기준이라 대체로 넓어진다.
- 서머타임 종료일(일요일)이 들어간 세션은 25시간, 시작일 세션은 23시간이다. 주말을 낀 세션 날짜 구분은 예전 22:30 고정 때와 같다(매일 리셋).
- 요청 봉 수가 최대 1600봉, 즉 토스 호출 최대 8회/주기로 늘어난다. 가상봇은 실봇 브로커로 시세를 받으므로 4개가 모두 켜져 있으면 분당 최대 약 32회다. 토스 시세 한도(초당 20회) 안이지만 주기당 지연이 1~3초 늘 수 있다.
- RSI/ADX는 더 긴 봉으로 계산된다. Wilder EWM이라 150봉 이후 초기값 영향이 1e-5 수준이므로 값 차이는 무시할 만하다.

### 나중에 이 결정을 뒤집게 된다면
- **D3만 되돌리기**(예전 150봉 창으로): `bot.py`에서 `candle_count = session.bars_needed(...)`를 `150`으로 바꾸면 된다. D1·D2는 그대로 유지할 수 있다.
- **고정 22:30으로 되돌리기**: 해당 모드의 `reset_time`을 22:30/23:30이 아닌 값으로 바꾸면 고정 모드가 된다. 코드로 되돌리려면 `SessionSpec.for_market`이 항상 `reset_time_mode`를 반환하게 하면 된다.
- 리플레이·봉 적재(ADR-0007)의 `session_date`는 `get_session_date(reset_time)` 대신 `SessionSpec.for_market(...).session_key`를 써야 운영과 맞는다. 3단계 구현 때 반영한다.

## 검토한 대안과 기각 근거

| # | 대안 | 판정 |
|---|---|---|
| B1 | **중단된 작업 그대로**: 미국 종목은 정규장 09:30~16:00 봉만 VWAP에 누적하고, 정규장 밖·데이터 미완성 시 신규 매수 금지 | **기각.** 실거래 체결의 상당수가 정규장 밖이므로 매매 규칙의 큰 변경이다(F1/F2 범위 밖). 페이징이 미확인인데 데이터가 미완성이면 매수를 영구 보류하는 구조라 운영이 멈출 위험이 있었다. 회귀 테스트 다수 실패. 4단계 후보로 남긴다. |
| B2 | 새 설정 키 `{mode}_session_mode`(auto/manual) + UI 노출 | **기각.** 키 추가 시 `config_manager` 기본값·API 화이트리스트·UI 3곳을 같이 바꿔야 한다. reset_time 값 규칙(D2)으로 같은 효과를 얻는다. |
| B3 | `zoneinfo("America/New_York")` 사용 | **기각.** Termux에 tzdata가 없으면 실패한다. 규칙 직접 계산이 단순하고, 테스트로 zoneinfo와 5년치 일치를 확인했다. |
| B4 | 150봉 유지, 자정 리셋만 제거 | **보류(사용자 선택지).** 변경이 가장 작지만 F1 효과가 00:00~01:00 정도에 그친다. 사용자가 "VWAP 체감 변화가 너무 크다"고 판단하면 D3만 되돌리는 방식으로 이 안을 택할 수 있다. |
| B5 | 페이징 미완성 시 신규 매수 보류 | **기각(이번 범위).** 매매 규칙 변경이고, 미확인 API 가정에 매매를 묶는다. 관측(로그·status)만 한다. |
