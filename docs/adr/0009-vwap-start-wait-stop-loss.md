# ADR-0009: VWAP 거래 시작 시각 대기 중에도 보유 포지션 손절·매도 허용 (신규 매수만 차단)

- **날짜**: 2026-10-07
- **상태**: **Accepted** — 사용자 결정("지금 고치기", 2026-10-07). 로컬 구현·테스트 완료, **S9 미배포**.
- **대상**: `my_butler` VWAP 자동매매 서브시스템 (REAL·가상 1~3·섀도우 — 모두 같은 `bot.py _loop_step` 사용)
- **선행 문서**: [ADR-0007](0007-vwap-shadow-replay-strategy-plugin.md)(전략 플러그인), [ADR-0008](0008-vwap-session-boundary.md)(세션 경계, D5 거래 시작 시각 보정)
- **관련 파일**: `core/vwap/bot.py`(7-1, 9-2-0), `core/vwap/strategies/rules.py`(`start_wait_blocks` 추가), `core/vwap/strategies/s0_current.py`, `scripts/test_vwap_stage3_plugin.py`(T-P1c·T-P3·T-P4 갱신, T-P5 신규)
- **관련 커밋**: (미커밋)
- **번호 메모**: ADR-0007/0008 에서 "4단계(전략 재연구) ADR = 0009"라고 적었으나, 이 ADR 이 0009 를 쓰므로 **4단계 ADR 은 0010** 이 된다.

---

## 배경 / 문제

3단계 SR-1(전략 플러그인) 작업 중 기존 동작 하나를 발견했다.

- 설정 `{mode}_start_time`(거래 시작 시각)을 쓰면, 세션 시작 ~ 거래 시작 시각 사이 **대기 구간** `[T_reset, T_start)` 동안 `bot.py` 7-1 이 전략 신호를 **무조건 `WAIT`로 덮어썼다.**
  - 보유 중 `STOP_LOSS`(손절가 이탈 → 시장가 청산)도 `WAIT`로 덮였다.
  - 이어서 9-4(HOLD/WAIT 분기)가 **미체결 주문을 전부 취소**했다. 걸어둔 지정가 매도도 사라졌다.
- 결과: **전 세션에서 넘어온 포지션은 대기 구간 동안 손절 보호를 전혀 받지 못했다.** 예) 리셋 22:30, 시작 23:30 이면 22:30~23:29 한 시간 동안 가격이 손절가 아래로 떨어져도 봇은 아무것도 하지 않는다. 일 손실한도(패닉) 하나만 남는데, 그건 계좌 단위 한도라 종목 손절보다 훨씬 늦게 발동한다.
- 현재 운영 설정의 `start_time`은 모두 빈 값이라 **지금 당장 영향은 없다.** 하지만 UI 에서 언제든 켤 수 있는 기능이고, 켜는 순간 보호가 사라지는 함정이다.
- 대시보드 설명과 사유 문구는 원래부터 "신규 매매 대기"였다. 즉 의도는 "새로 들어가지 않는다"였고, 기존 포지션 관리까지 멈추는 것은 구현이 의도보다 넓었던 것으로 판단한다.

## 결정

### D1. 대기 중 막는 것은 "신규 진입"뿐이다.
대기 구간에서 7-1 은 아래 조건일 때만 신호를 `WAIT` / 사유 `WAIT_START_TIME` 으로 덮는다.

```
is_waiting_for_start and (qty <= 0 or signal == "BUY")
```

| 상황 (대기 구간) | 전략 신호 | 이전 동작 | 이후 동작 |
|---|---|---|---|
| 보유 + 손절가 이탈 | STOP_LOSS | WAIT → 아무것도 안 함, 미체결 전부 취소 | **STOP_LOSS → 미체결 취소 후 시장가 청산** (평소와 동일) |
| 보유 + VWAP 위 | SELL | WAIT → 걸어둔 매도까지 취소 | **SELL → 지정가 매도 제출/정정** (평소와 동일) + 남은 매수 미체결 취소(D3) |
| 보유 + 그 사이 | HOLD | WAIT → 미체결 전부 취소 | HOLD → 미체결 전부 취소 (평소 HOLD 와 동일, 결과적으로 이전과 같음) |
| 무보유 + VWAP 아래 | BUY | WAIT → 매수 안 함 | WAIT → 매수 안 함 (변화 없음) |
| 무보유 + VWAP 위/필터 | WAIT | WAIT_START_TIME | WAIT_START_TIME (변화 없음) |

무보유일 때는 전략이 `WAIT`를 내도 사유를 `WAIT_START_TIME`으로 바꾸는 기존 동작을 유지한다(대시보드 "시작 대기" 표시 유지). 보유 중에는 사유도 전략 사유(STOP_LOSS, SELL_ARMED 등)를 그대로 보여준다. 상태 필드 `waiting_for_start`는 보유 여부와 관계없이 "지금이 대기 구간인가"를 그대로 나타낸다.

### D2. 대기 중 SELL(익절·VWAP 위 매도)도 허용한다 — "보유 포지션 관리 전체 허용".
손절만 허용하고 SELL 은 막는 방안(아래 C2)도 검토했으나, 보유 포지션 관리 전체(STOP_LOSS·SELL·HOLD)를 평소대로 두는 쪽을 택했다. 근거는 "근거" 절 참고.

### D3. 대기 중 보유 SELL 주기에는 남아 있는 매수 미체결을 먼저 취소한다 (9-2-0).
부분 체결 잔량 같은 매수 미체결이 남아 있는데 SELL 분기로 가면, 기존 9-2 는 매수 주문을 건드리지 않는다. 그 주문이 대기 중 체결되면 "대기 중 신규 진입"이 된다. 이전 동작(9-4 에서 전부 취소)이 보장하던 "대기 중 매수 없음"을 지키기 위해 대기 중 SELL 주기에만 매수 미체결을 취소한다.
- HOLD/WAIT 는 9-4 가, STOP_LOSS 는 청산 경로가 이미 모든 미체결을 취소하므로 따로 처리하지 않는다.
- **대기 밖의 같은 상황(보유 + SELL + 매수 잔량)은 기존 동작 그대로 둔다.** 이번 범위가 아니다.

### D4. 9-4(미체결 정리) 규칙은 바꾸지 않는다.
D1 로 9-4 에 들어오는 경우가 "무보유 대기(WAIT)"와 "보유 HOLD"뿐이 됐다. 둘 다 평소에도 미체결을 전부 취소하는 경우이므로 "신규 매수 차단 + 보유 포지션은 평소대로" 원칙과 이미 맞는다.

### D5. 플러그인 규칙·연구 엔진
- `core/vwap/strategies/rules.py`에 `start_wait_blocks(signal, position_qty)`를 추가하고, `S0CurrentStrategy.evaluate`가 같은 조건으로 덮는다. `bot.py`는 여전히 이 함수를 호출하지 않고(ADR-0007 D1, REAL 경로 직접 의존 회피) 같은 조건을 직접 쓴다. 동치는 테스트 T-P4·T-P5 가 실제 `_loop_step` 결과와 대조해 보장한다.
- 연구 엔진 `backtest.strategies.S0_Current`는 **바꾸지 않는다**(`backtest/`는 검증 하네스). 원래 start_time 을 모델링하지 않으므로, start_time 을 쓰는 리플레이 결과는 연구 엔진과 다를 수 있다. 그 차이가 "대기 중 무보유 매수 차단" 하나뿐임을 T-P3 가 테스트로 보인다(`S0_Current + 무보유 매수 차단` == 플러그인, 거래·자산곡선 완전 일치).

## 근거

- **손절은 보호 장치다.** 거래 시작 시각은 "장 초반 변동성/얇은 VWAP 구간에 새로 들어가지 않기"를 위한 기능이다. 이미 들고 있는 위험을 줄이는 행동(손절·매도)까지 막을 이유가 없다. 오히려 장 초반 변동성이 크다는 그 이유 때문에 손절이 더 필요하다.
- **SELL 도 허용하는 이유**
  1. SELL 은 위험을 줄이는 방향이다. 보유 수량을 늘리는 행동이 아니다.
  2. SELL 을 막으려면 "대기 중 SELL → 기존 매도 주문은 유지하되 정정은 안 함" 같은 **새 분기**가 필요하다. 9-4 가 전부 취소하는 현 구조에서 이를 지키려면 9-4 를 둘로 쪼개야 하고, 테스트할 조합이 늘어난다. 지금 요구(손절 보호)보다 큰 변경이다.
  3. 대기 구간의 보유 포지션 동작이 **대기 없음 설정과 완전히 같아진다.** "보유 중이면 start_time 은 아무 영향이 없다"는 한 문장으로 설명된다(초보 사용자 가이드에 그대로 씀). 리플레이에서도 연구 엔진 S0_Current 와의 차이가 "무보유 진입 차단"으로 깔끔하게 한정된다.
  4. 장 초반 VWAP 이 얇아 매도 타겟이 불안정할 수 있다는 우려는 있다. 그러나 SELL 은 `현재가 ≥ VWAP` 일 때만 나오고, 타겟은 VWAP×(1+M%) 이라 평소와 같은 기준이다. 전략 품질 문제는 4단계(ADR-0010) 재연구에서 다룬다.
- **다른 보호 경로와 충돌 없음**
  - 일 손실한도(패닉): 7 단계(신호 계산)보다 **앞**에서 판정·청산·정지하고 return 한다. 대기 여부와 무관하며 이번 변경의 영향을 받지 않는다.
  - REAL 미체결 조회 실패: 기존부터 "STOP_LOSS 는 진행, 지정가 주문은 보류"다. 대기 중에도 이제 같은 규칙이 적용된다(T-P5 f). 9-2-0 은 조회 실패 return 뒤에 있어 조회 실패 주기에는 실행되지 않는다.
  - 데이터 조회 실패(캔들·잔고): 7-1 이전에 return 하므로 무관.

## 결과

### 좋아지는 것
- start_time 을 켜도 전 세션 보유 포지션이 손절가 이탈 시 즉시 시장가 청산된다.
- 보유 중 동작이 start_time 설정과 무관해져 설명·검증이 단순해진다.

### 감수하는 것
- **매매 동작 변경**이다(현재 운영 start_time 은 모두 빈 값이라 배포 직후 실제 차이는 없다).
- 대기 중 SELL 이 체결될 수 있다. 이전에는 대기 구간에 어떤 체결도 없었다.
- 리플레이(start_time 사용 시)는 연구 엔진 S0_Current 와 결과가 다르다. 의도된 차이이며 T-P3 로 명시했다.
- 9-2-0 매수 미체결 취소 요청이 실패하거나 취소 확정 전에 체결되면 대기 중 소량(남은 매수 잔량 이내)이 추가로 매수될 수 있다. 실패는 warn 이벤트로 남고 다음 주기에 재시도한다. 기존 9-4와 같은 수준의 위험이다.
- `bot.py`와 `rules.py`에 같은 조건이 두 번 있다(REAL 경로 무의존 원칙 유지 대가). T-P4·T-P5 가 불일치를 잡는다.

### 나중에 뒤집는다면
- "손절만 허용"(C2)으로 좁히려면 7-1 조건을 `qty <= 0 or signal in ("BUY", "SELL")` 로 바꾸고, 9-4 에서 대기 중 보유 시 기존 매도 주문을 유지하는 분기를 추가한다. `rules.start_wait_blocks`와 T-P5 기대값도 함께 바꾼다.
- 이전 동작(전부 WAIT)으로 되돌리려면 7-1 조건에서 `and (...)`를 제거하고 9-2-0 블록을 지운다. 권장하지 않는다.

## 검토한 대안과 기각 근거

| # | 대안 | 판정 |
|---|---|---|
| C1 | 현행 유지(대기 중 전부 WAIT) + 문서에 경고만 | **기각.** 사용자 결정이 "지금 고치기". 켜는 순간 손절 보호가 사라지는 함정이 남는다. |
| C2 | 대기 중 STOP_LOSS 만 허용, SELL 은 WAIT(기존 매도 주문은 유지) | **기각.** 9-4 를 "대기 중 보유면 매도 주문 유지"로 쪼개야 하는 새 분기가 필요하고, 위험을 줄이는 SELL 을 막을 근거가 약하다. 위 "나중에 뒤집는다면"에 전환 방법을 남김. |

| C4 | 거래 시작 시각 기능 자체 제거 | **기각.** 사용자 기능 삭제이고 설정·UI·API 화이트리스트를 같이 바꿔야 한다. 범위 밖. |
| C5 | bot.py 가 `rules.start_wait_blocks`를 직접 호출 | **보류.** 중복은 없어지지만 REAL 경로가 플러그인 패키지에 의존하게 된다(ADR-0007 D1: REAL 연결은 4단계에서 결정). 동치 테스트로 대신한다. |
