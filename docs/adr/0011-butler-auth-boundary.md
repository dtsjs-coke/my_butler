## 배경 / 문제

2026-10-07 조사에서 Butler API 토큰(`BUTLER_API_TOKEN`) 하나가 사실상 공개 상태였다. 위험도는 치명적으로 판단했다.

1. **공개 기본값**: 코드가 `os.getenv("BUTLER_API_TOKEN", <고정 문자열>)` 형태였고, S9 `.env` 의 실제 값이 이 기본값과 같았다. 이 코드는 공개 저장소에 있다.
2. **HTML 노출**: 인증 없는 페이지 5개(`/`, `/trains`, `/news`, `/settlement`, `/liquor`)가 `render_template(..., api_token=...)` 으로 토큰을 HTML 에 넣었다. 페이지를 한 번 열면 누구나 토큰을 얻는다.
3. **공인 IP 바인딩**: Flask 가 `0.0.0.0:5000` 에 떠 있었고 S9 는 공인 IPv4 를 받는다. 외부 스캐너가 `/` 에서 200 을 받은 기록이 있다(= 토큰이 든 HTML 수집).
4. **공개 저장소 자동 push**: `tunnel_manager` 가 터널 URL 이 바뀔 때마다 `subscription-manager/src/config.py` 에 URL 과 토큰을 써서 공개 저장소에 push 한다. 토큰을 바꿔도 다음 터널 재시작 때 다시 공개된다.

이 토큰으로 할 수 있던 일: `/users/*`(구독 앱 계정 정보 조회·덮어쓰기 → 계정 탈취), `/subscriptions/*`, `/send`(봇 명의 Discord 메시지 → 피싱), SRT 예약 큐 조작, 키워드·정산 변경. VWAP 매매 API 는 별도 admin 세션(`vwap_session`)으로 보호돼 이 토큰과는 무관했다. 다만 그 쿠키에도 `HttpOnly`/`SameSite`/`Secure` 속성이 없었다.

## 결정

### D1. 인증 수단을 용도별로 분리한다
- **사람(브라우저)** → VWAP 로그인으로 발급되는 admin 세션 쿠키 `vwap_session`. 새 계정 체계를 만들지 않고 기존 VWAP admin 비밀번호를 재사용한다.
- **기계(구독 앱·터널 알림·로컬 스크립트)** → `X-Butler-Token` 헤더 + `.env` 의 `BUTLER_API_TOKEN`.
- 토큰은 **어떤 HTML 에도 넣지 않는다**. 템플릿에는 토큰을 넘기지 않는다.

### D2. 토큰은 fail-closed, 상수 시간 비교
- 코드에 기본값을 두지 않는다. 요청 시점에 환경변수에서 읽고, 비어 있거나 공백뿐이면 **모든 토큰 인증을 거부**한다.
- 비교는 `hmac.compare_digest`.

### D3. 라우트별 권한

| 구분 | 경로 | 권한 |
|---|---|---|
| 비공개 페이지 | `/`, `/trains` (및 앞으로 추가되는 페이지의 기본값) | admin 세션. 없으면 302 `/vwap/?next=<원래 경로>` |
| 공개 페이지 | `/settlement`, `/liquor`, `/news` | 없음 |
| 대시보드 API | `/api/system_status`, `/api/srt/queue`, `/api/srt/reserve`, `/api/keywords`(GET 포함), `/api/keyword_groups` POST·DELETE | 세션 **또는** 토큰 (`session_or_token`) |
| 기계 전용 API | `/users/*`, `/subscriptions/*` | 토큰만 (`token_only`). 세션만으로는 401 |
| 메시지 전송 | `/send` | 로컬 직접 요청(원격 주소 127.0.0.1/::1, `Cf-Connecting-IP`·`CF-Ray`·`Cdn-Loop`·`X-Forwarded-For` 헤더 없음) **그리고** 토큰 (`local_send_only`). 위치 위반은 토큰 판정 전에 403 |
| 주류 | `GET /api/liquor_purchases` 공개 / 쓰기·병합·무시·가져오기 | admin 세션 (`admin_required` 유지, 토큰 요구는 제거) |
| 뉴스 | `GET /api/keyword_groups` 공개(뉴스 그룹 필터) | 수정은 세션 또는 토큰 |
| 정산 | `GET/POST/DELETE /api/settlements` | **공개 유지** (D5) |
| VWAP | `/vwap/api/*` | 기존 `admin_required` 그대로(세션 쿠키 또는 Bearer). API 토큰으로는 불가 |

### D4. 네트워크 경계
- Flask 를 `127.0.0.1:5000` 에만 바인딩한다. cloudflared 는 이미 `http://127.0.0.1:5000` 으로 접속하므로 터널 경로는 바뀌지 않는다.
- cloudflared 요청은 원격 주소가 127.0.0.1 로 보이므로, 터널 요청 판별은 Cloudflare 엣지가 붙이는 헤더로 한다. 외부 공격자는 이 헤더를 지울 수 없다.

### D5. 정산은 공개 쓰기를 유지하고 위험을 줄인다
코드상 정산 페이지는 참석자 기본값이 친구 6명으로 박힌 공유 계산기이고, 저장·불러오기·삭제가 같은 목록 하나를 쓴다(사용자 구분 없음, 7일 뒤 자동 삭제). 친구가 로그인 없이 저장하는지는 코드로 확정할 수 없어서 **기능을 유지**한다. 대신:
- **저장형 XSS 차단**: 이 페이지는 제목·이름·메모를 `innerHTML`, 속성 값, `onclick` 문자열에 그대로 넣는다. 같은 출처에 VWAP admin 화면이 있으므로, 여기서 스크립트가 실행되면 admin 쿠키로 실거래 API 를 호출할 수 있다. 서버에서 모든 문자열(딕셔너리 키 포함)에 `<`, `>`, `"`, `'`, 백틱, `&`, 역슬래시, 제어문자가 있으면 거부한다(400 `invalid_chars`). 템플릿 쪽 이스케이프도 함께 한다(UI 후속).
- **상한**: 본문 64KB(413), 제목 100자, 문자열 200자, 참석자 50, 항목 200(400 `too_large`), 보관 50건(409 `too_many_saved`), `id` 는 숫자 문자열만.
- **원자적 쓰기 + 잠금**: 임시 파일 → `os.replace`, `RLock`.
- 스위치 `SETTLEMENT_PUBLIC_WRITE`(기본 True)를 False 로 바꾸면 쓰기만 세션 또는 토큰을 요구한다(조회는 공개 유지).
- **확정(2026-10-07 사용자 결정)**: 친구들도 직접 저장하므로 `SETTLEMENT_PUBLIC_WRITE = True` 유지, 위험 문자 차단 유지.

### D6. 세션 쿠키 강화
- `vwap_session` 에 `HttpOnly`, `SameSite=Lax`, `Secure`, `Path=/`, `Max-Age=86400`. 로그아웃도 같은 속성으로 만료시킨다.
- 로그인 응답 본문에서 세션 토큰을 뺀다(쿠키로만 전달). 기존 화면은 본문 토큰을 쓰지 않았다.
- `SameSite=Lax` 이므로 다른 사이트에서 보낸 POST/DELETE 에는 쿠키가 실리지 않는다. 상태를 바꾸는 API 는 모두 GET 이 아니므로 별도 CSRF 토큰은 두지 않는다.

### D7. 로그인 후 복귀
- 비공개 페이지 → `/vwap/?next=<경로>`. 로그인 화면은 성공 시 `location.reload()` 하므로, 같은 URL 이 세션과 함께 다시 들어오면 `/vwap/` 가 `next` 로 302 한다(로그인 화면 JS 수정 없이 동작).
- `next` 는 `/` 로 시작하는 같은 사이트 상대 경로만 허용(`//`, `\`, 스킴, 제어문자 거부 → 오픈 리다이렉트 방지).

### D8. 토큰을 공개 저장소에 쓰지 않는다 (후속 구현)
- `tunnel_manager` 는 `subscription-manager` 에 URL 만 쓰고 토큰은 쓰지 않는다. 구독 앱은 토큰을 Streamlit secrets / GitHub Actions secrets 에서 읽는다.
- 토큰 기본값 문자열은 모든 클라이언트 코드에서 제거한다. 토큰이 비어 있으면 호출하지 않거나 실패를 로그로 남긴다.

### D9. 로그인 시도 제한 (`POST /vwap/login`, `api/login_throttle.py`)
D1 로 대시보드 전체가 VWAP admin 비밀번호 하나에 걸리게 됐으므로, 그 비밀번호를 무차별 대입으로 맞히지 못하게 한다.
- **클라이언트 키**: `Cf-Connecting-IP` 헤더가 있으면 그 값, 없으면 `remote_addr`. 터널 요청은 원격 주소가 모두 127.0.0.1 이라 원격 주소만으로는 구분할 수 없다. 로그에도 쓰므로 `[0-9A-Za-z:.-]` 외 문자는 `?` 로 바꾸고 64자로 자른다.
- **키별 잠금**: 같은 키가 10분 안에 5번 틀리면 15분 잠금. 로그인에 성공하면 그 키의 실패 기록과 잠금을 지운다.
- **전역 상한**: 헤더는 위조될 수 있으므로(같은 기기 프로세스 등) 키와 무관하게 전체 실패를 센다. 최근 10분 실패가 20회 이상이면 그동안은 **30초에 한 번만** 비밀번호를 검사한다. 위조 키를 무한히 바꿔도 검사는 하루 최대 약 2,880회로 묶이고, S9 CPU 를 KDF(D10)로 소진시키지도 못한다.
  - 같은 기기에서 직접 붙은 요청(원격 주소 127.0.0.1/::1, 터널 헤더 없음 — `auth.is_direct_local_request`)은 전역 상한에서 뺀다. 키별 잠금은 그대로 받는다(키 `127.0.0.1`). 외부 요청은 모두 터널을 거쳐 Cloudflare 헤더가 붙으므로 이 예외를 쓸 수 없다. 소유자가 공격 중에도 `ssh -L` 등으로 로그인할 수 있는 복구 경로다.
- **잠긴 동안에는 올바른 비밀번호도 받지 않는다(검사 자체를 하지 않는다).** 검사해서 맞으면 받아 준다면 '틀림 → 429, 맞음 → 200' 이 되어 잠금 중에도 정답 판정을 무제한으로 얻을 수 있다. 소유자 쪽 부담은 작다: 키별 잠금은 그 키가 스스로 5번 틀렸을 때만 걸리고(최대 15분), 전역 상한은 최대 30초 대기다. 급하면 `pm2 restart` 로 즉시 해제된다(아래 메모리 보관). → 하단 정정 메모 참조
- **응답**: HTTP 429, 본문 `{"status":"failed","reason":"too_many_attempts","retry_after":<정수 초>}`, 헤더 `Retry-After: <같은 값>`, 쿠키 없음. 틀린 비밀번호는 기존대로 401 `invalid_password`(남은 횟수는 알려주지 않음).
- **동시 요청**: 검사를 허용하는 순간 그 시도를 실패로 먼저 기록하고(가예약) 성공하면 지운다. 같은 키로 동시에 여러 요청을 보내도 검사 전에 한도가 적용된다.
- **보관 위치: 프로세스 메모리**(재시작 시 초기화 허용). 근거: (1) 실패마다 디스크에 쓰면 공격자가 S9 저장소 쓰기를 유발한다, (2) Flask 는 단일 프로세스(`threaded=True`)라 공유가 필요 없다, (3) 외부 공격자는 서버를 원격으로 재시작시킬 수 없어 초기화를 악용하기 어렵다, (4) 재시작이 소유자의 비상 해제 수단이 된다. 키 저장 수는 2,000개로 상한.
- **기록**: 실패할 때마다 `butler_auth` 로거에 WARNING(키, 최근 실패 횟수, 잠금 여부 — 비밀번호는 남기지 않음), 전역 제한 시작/해제도 WARNING. 429 거부는 건마다 남기지 않는다(공격자가 로그를 무한히 늘리지 못하게). PM2 로그로 확인한다. **VWAP 이벤트(`vwap_events_*.jsonl`)에는 남기지 않는다**: 그 파일은 매매 모드별 타임라인이고 Discord 알림과 연결돼 있어, 로그인 실패를 넣으면 매매 기록이 오염되고 공격자가 알림·디스크 쓰기를 유발할 수 있다.

### D10. admin 비밀번호 해시 강화 + 자동 마이그레이션 (`core/vwap/crypto.py`)
- **형식**(문자열 하나에 알고리즘·파라미터·salt·결과):
  - `scrypt$n=16384,r=8,p=2$<salt>$<hash>` — 우선
  - `pbkdf2_sha256$i=400000$<salt>$<hash>` — scrypt 를 쓸 수 없을 때
  - salt 16바이트(`os.urandom`), 결과 32바이트, 둘 다 base64url(패딩 없음). 옛 형식은 64자리 소문자 hex(salt 없는 SHA-256).
- **표준 라이브러리만** 쓴다(`hashlib.scrypt`, `hashlib.pbkdf2_hmac`, `hmac.compare_digest`). bcrypt/argon2 는 S9 에 없을 수 있다.
- **파라미터 근거**: 로컬 PC(Intel Core Ultra)에서 scrypt(n=2^14,r=8,p=2) 검증 약 0.07초, pbkdf2 40만 회 약 0.08초. S9(Exynos 9810) 단일 코어를 6~8배 느리다고 보고 S9 에서 0.4~0.6초를 목표로 했다. scrypt 메모리는 `128·r·n` = 16MiB 로, n 을 키우는 대신 p 로 시간을 늘려 동시 로그인 시 메모리 부담을 제한했다(OWASP 의 n=2^14 계열 권장보다 p 가 낮은 것은 S9 지연 목표 때문). 파라미터는 문자열에 들어 있으므로 나중에 바꿔도 기존 해시는 검증되고 다음 로그인 때 새 값으로 갱신된다.
- **런타임 감지**: 처음 쓸 때 `hashlib.scrypt` 가 있는지, 작은 값으로 호출되는지 확인해 캐시한다. 실제 파라미터에서 실패하면(메모리 한도 등) 그 자리에서 pbkdf2 로 대체하고 이후 pbkdf2 만 쓴다. S9(Termux python, OpenSSL 3.x)에서는 scrypt 가 있을 것으로 보지만 접속해 확인하지 못했으므로 코드가 둘 다 처리한다.
- **검증**: `verify_password(pw, stored) -> (일치, 재해시 필요)`. 비교는 모두 `hmac.compare_digest`. 형식이 틀리거나 파라미터가 허용 범위 밖이면(예: n 이 2의 거듭제곱이 아님, n>2^20, 반복 횟수 1만 미만/500만 초과) 예외 없이 불일치. 비밀번호가 문자열이 아니거나 1024자를 넘으면 불일치.
- **자동 마이그레이션**: 로그인이 성공했는데 저장 형식이 옛 SHA-256 이거나 지금 기준보다 약하면(pbkdf2 인데 scrypt 가능, 파라미터가 낮음) 그 자리에서 새 형식으로 재해시해 `vwap_config.json` 에 저장한다. 사용자는 비밀번호를 바꿀 필요가 없다.
  - 저장은 `save_config` 와 같은 파일·같은 원자적 쓰기(`_write_json_atomic`: 같은 폴더 임시 파일 → `os.replace`, 잠금)를 쓰되, 파일 원본 JSON 에서 `admin_password_hash` 한 키만 바꾼다(`update_admin_password_hash`). `load_config` 결과를 통째로 저장하지 않는 이유: `.env` 값이 섞이고, 파일이 손상돼 읽지 못하면 기본값을 돌려주기 때문에 설정 파일을 덮어쓸 수 있다.
  - 파일이 없거나 손상됐으면 저장하지 않는다(로그인은 성공). 그 사이 파일의 해시가 다른 값으로 바뀌었으면 덮어쓰지 않는다. 갱신 실패는 로그인을 막지 않고 다음 로그인 때 다시 시도한다.
  - 이번 변경으로 `save_config` 도 원자적 쓰기로 바뀌었다(기존에는 파일을 바로 열어 썼다).
- **설정 로드의 대체 해시**: 설정 파일에 해시가 없을 때 `load_config` 는 `.env` 의 `VWAP_ADMIN_PASSWORD`(없으면 기본값)로 대체 해시를 만든다. `load_config` 는 봇 주기마다 불리므로 여기서는 느린 KDF 대신 옛 형식(`legacy_hash_password`)을 쓰고, 그 값으로 로그인에 성공하면 위 마이그레이션으로 파일에 새 형식이 기록된다.
- **비밀번호 변경**(`POST /vwap/api/config` 의 `new_admin_password`)은 새 형식으로 저장한다. 문자열이 아니거나 1024자를 넘으면 400 `invalid_value`.

## 근거

- 노출 경로 4개(D2 기본값, D1 HTML, D4 바인딩, D8 자동 push)를 모두 막아야 토큰 교체가 의미가 있다. 하나라도 남으면 새 토큰이 다시 공개된다.
- 사람용 인증을 새로 만들지 않고 VWAP admin 세션을 재사용하면, 실거래 화면과 같은 수준의 보호를 추가 코드 거의 없이 얻는다. 이 대시보드의 관리자는 한 명이다.
- `/send` 는 봇 명의로 아무 채널에나 쓸 수 있어 피싱 위험이 가장 크다. 호출자는 모두 같은 기기의 프로세스(VWAP 알림, 터널 알림, butler_agent)라서, 외부에서 부를 이유가 없다.
- 정산은 사용자가 공개를 택한 페이지다. 쓰기까지 막으면 기능이 바뀔 수 있으므로, 위험 요소(같은 출처 XSS, 디스크 고갈, 파일 손상)만 제거한다. 사용자가 공개 쓰기 유지를 확정했다.
- D1 로 대시보드·실거래 화면이 모두 admin 비밀번호 하나에 걸리게 됐다. 그 비밀번호를 지키는 두 가지(온라인 대입 제한 D9, 저장 해시가 새어도 역산이 어렵게 하는 D10)가 없으면 인증 경계 전체가 그 비밀번호 강도에만 의존한다.

## 기각한 대안

| # | 대안 | 기각 이유 |
|---|---|---|
| R1 | 토큰 값만 교체 | HTML 노출·자동 push 가 그대로라 새 토큰도 즉시 다시 공개된다. |
| R2 | 모든 페이지를 비공개 | 사용자가 정산·주류 조회·뉴스를 공개로 결정했다. |
| R3 | Flask-Login 등 새 세션/계정 체계 | 관리자 1명인 개인 대시보드에 의존성과 코드만 늘어난다. 기존 VWAP admin 세션으로 충분하다. |
| R4 | Cloudflare Access 로 터널 앞단 인증 | quick tunnel(`trycloudflare`)은 Access 를 붙일 수 없고, 계정 터널 전환은 별도 인프라 작업이다. 공개 페이지 요구와도 맞지 않는다. 장기 후보로 남긴다. |
| R5 | `/send` 를 토큰만으로 계속 허용 | 토큰이 다시 새면 그대로 피싱 통로가 된다. 로컬 호출자만 있으므로 위치 제한의 비용이 없다. |
| R6 | `/send` 를 별도 포트·유닉스 소켓으로 분리 | 더 강하지만 호출자 3곳과 PM2 구성을 함께 바꿔야 한다. 127.0.0.1 바인딩 + 터널 헤더 검사로 같은 목적을 이룬다. |
| R7 | 정산 쓰기를 admin 전용으로 | 친구들의 저장·삭제가 막힐 수 있다(코드로 사용 방식 확정 불가). 스위치로 언제든 전환 가능하게 두고 사용자에게 확인한다. |
| R8 | 정산 입력값을 서버에서 이스케이프해 저장 | 저장 데이터가 HTML 엔티티로 오염되고, 화면마다 이중 이스케이프 문제가 생긴다. 위험 문자 거부(서버) + 출력 이스케이프(템플릿)로 나눈다. |
| R9 | 별도 CSRF 토큰 | 상태 변경 API 가 모두 비-GET 이고 `SameSite=Lax` + JSON 본문이라 추가 이득이 작다. |
| R10 | 페이지에 토큰 대신 짧은 수명의 서명 토큰 주입 | 공개 페이지에서는 결국 누구나 받는 값이라 보호가 되지 않는다. 비공개 페이지는 쿠키로 충분하다. |
| R11 | (D9) 잠금 중에도 올바른 비밀번호는 받아 준다 | 비밀번호를 검사하는 순간 잠금 중에도 정답 판정이 나간다(맞으면 200). 잠금이 공격자를 막지 못한다. |
| R12 | (D9) 전역 상한을 '완전 잠금'으로 | 위조·분산 키로 실패 20회만 만들면 소유자를 계속 잠글 수 있다(서비스 거부). '30초에 1회 검사'는 대입 속도를 묶으면서 소유자는 최대 30초 대기로 들어올 수 있다. |
| R13 | (D9) 실패 기록을 파일에 보관 | 실패마다 디스크 쓰기가 생기고(공격자가 유발 가능) 파일 손상 처리가 필요하다. 단일 프로세스라 메모리로 충분하고, 재시작 초기화는 원격에서 악용하기 어렵다. |
| R14 | (D9) `X-Forwarded-For` 등 다른 헤더도 클라이언트 키로 | 클라이언트가 임의로 넣을 수 있다. Cloudflare 가 덮어쓰는 `Cf-Connecting-IP` 하나만 쓴다. |
| R15 | (D10) bcrypt / argon2 | 외부 패키지다. S9(Termux)에 빌드·설치가 안 될 수 있다. 표준 라이브러리 scrypt/pbkdf2 로 충분하다. |
| R16 | (D10) 사용자에게 비밀번호 재설정을 요구 | 불필요하다. 로그인 성공 시점에 평문이 있으므로 그 자리에서 재해시할 수 있다. |
| R17 | (D10) `load_config` 에서 대체 해시도 새 형식으로 | `load_config` 는 봇 주기마다 불려 매번 0.5초짜리 KDF 를 돌리게 된다(salt 가 달라 값도 매번 바뀜). 대체값은 옛 형식으로 두고 로그인 성공 시 파일로 올린다. |
| R18 | (D10) 마이그레이션을 `load_config` → `save_config` 로 통째 저장 | `.env` 값이 파일에 섞이고, 손상 파일을 기본값으로 덮어쓸 수 있다. 해시 한 키만 원자적으로 바꾼다. |

## 결과

- 좋아지는 점: 토큰이 HTML·코드 기본값·공개 저장소에서 사라진다. 외부에서 `/send`·`/users`·`/subscriptions` 를 쓸 수 없다. 대시보드는 로그인한 관리자만 조작한다. 세션 쿠키를 스크립트가 읽을 수 없다. admin 비밀번호는 IP 당 10분 안에 5번 틀리면 15분 잠기고, 실패가 몰리면 전체로 30초에 1회만 검사한다. 저장된 해시는 salt 가 있는 scrypt(또는 pbkdf2)라 파일이 새어도 미리 계산한 표나 빠른 대입으로 역산하기 어렵다. 기존 해시는 첫 로그인 때 저절로 바뀐다.
- 부담:
  - 비공개 페이지(`/`, `/trains`)와 뉴스 키워드 관리는 이제 로그인이 필요하다. 로그인은 VWAP 비밀번호와 같다.
  - `Secure` 쿠키라 `http://<LAN IP>:5000` 접속에서는 로그인이 유지되지 않는다. 바인딩이 127.0.0.1 이라 원래 그 경로는 막힌다(터널 https 또는 S9 자체 localhost 만 사용).
  - 정산은 누구나 쓰고 지울 수 있다(D5, 사용자가 공개 쓰기 유지를 확정).
  - 토큰을 교체하면 `.env`(S9), 구독 앱 secrets(Streamlit Cloud, GitHub Actions)를 같이 바꿔야 한다.
  - (D9) 소유자도 5번 틀리면 15분 동안 그 IP 에서 로그인할 수 없다. 즉시 풀려면 `pm2 restart`(시도 제한 상태는 메모리에만 있음). 공격이 계속되는 동안은 전역 상한 때문에 최대 30초 기다려야 할 수 있다. → 하단 정정 메모 참조 로그인 화면은 429 와 `retry_after` 를 보여 줘야 한다(UI).
  - (D10) 로그인 1회에 S9 에서 약 0.5초(추정)가 더 걸린다. 첫 로그인 성공 때 `vwap_config.json` 의 해시가 한 번 바뀐다. 해시를 새 형식으로 만든 뒤 런타임에서 scrypt 를 잃으면(OpenSSL 교체 등) 검증할 수 없어 로그인이 실패한다. 복구는 `vwap_config.json` 의 `admin_password_hash` 를 비우고 `.env` 의 `VWAP_ADMIN_PASSWORD` 로 로그인하는 것(그때 pbkdf2 로 다시 저장됨). → 하단 정정 메모 참조(M3: 이 방법은 쓰지 말 것)
  - `save_config` 가 임시 파일 → `os.replace` 로 바뀌어, 설정 파일 권한이 `mkstemp` 기본값(소유자만 읽기/쓰기, 0600)이 된다.
- 남은 위험(이번 범위 밖): 공개 저장소 이력에 남은 과거 토큰·사용자 해시는 지워지지 않는다(교체로만 무력화). 정산 쓰기에 속도 제한이 없다. 비밀번호를 바꿔도 이미 발급된 세션 쿠키(최대 24시간)는 무효화되지 않는다. 설정 파일에 해시가 없고 `.env` 에 `VWAP_ADMIN_PASSWORD` 도 없으면 코드의 기본 비밀번호가 그대로 쓰인다 — **운영 비밀번호가 기본값이 아닌지 배포 전에 확인해야 한다**(D9·D10 은 약한 비밀번호를 지켜 주지 못한다).
- 참고: `VwapConfigManager.load_config()` 가 호출마다 `.env` 를 `override=True` 로 다시 읽으므로, 실행 중 `.env` 의 토큰을 바꾸면 재시작 전에도 반영될 수 있다. 배포 절차는 재시작을 전제로 한다.

## 되돌리는 방법

- 전체 롤백: 기준 커밋 `94ce5fa` 의 `api/flask_app.py`·`api/vwap_api.py`·템플릿으로 되돌리고 `api/auth.py` 를 지운다. 단, 되돌리면 노출 4경로가 다시 열리므로 **토큰 교체 전에는 롤백하지 않는다**. 롤백한다면 최소한 바인딩 `127.0.0.1` 과 기본값 제거는 남긴다.
- 부분 조정
  - 페이지 공개/비공개: 해당 라우트에 `@page_login_required` 를 붙이거나 뗀다.
  - 정산 쓰기 보호: `SETTLEMENT_PUBLIC_WRITE = False`.
  - 쿠키 속성: `api/auth.py` 의 `set_session_cookie` 한 곳.
  - `/send` 터널 헤더 목록: `api/auth.py` 의 `PROXY_HEADERS`.
  - 시도 제한 수치: `api/login_throttle.py` 의 `LoginThrottle` 클래스 상수(`PER_KEY_MAX`, `LOCKOUT`, `GLOBAL_THRESHOLD`, `GLOBAL_INTERVAL` 등). 끄려면 `vwap_login` 의 `acquire` 검사를 제거.
  - 해시 파라미터: `VwapCrypto.PW_SCRYPT_*`, `PW_PBKDF2_ITER`. 바꿔도 기존 해시는 계속 검증되고 다음 로그인 때 새 값으로 갱신된다.
  - 해시를 옛 코드로 되돌리면 옛 코드는 새 형식을 읽지 못한다 → 되돌리기 전에 `vwap_config.json` 의 `admin_password_hash` 를 비우거나 SHA-256 hex 로 바꿔 둔다. → 하단 정정 메모 참조(M3: 비우지 말고 새 비밀번호의 SHA-256 hex 로 교체)

### M2. NaN/Infinity 저장으로 목록이 깨짐 (D5 정정)
- Python `json` 은 `NaN`/`Infinity` 와 `1e999`(→ inf)를 기본으로 받아들이고 그대로 내보내, 브라우저 `JSON.parse` 가 실패해 정산 목록 전체가 깨졌다. 이제 파싱 때 `parse_constant`·`parse_float` 로 거부(400), 값 검증에서 `math.isfinite` 만 허용, 응답과 파일 쓰기는 `allow_nan=False`.

### P1. 코드의 기본 비밀번호 대체를 없앤다 (D10 "설정 로드의 대체 해시", "결과" 남은 위험 마지막 문장 정정)

- 서버 로그: `butler_auth` 로거에 경고를 남긴다. "관리자 비밀번호가 설정되지 않아 로그인이 비활성화됨 — .env VWAP_ADMIN_PASSWORD 설정 후 재시작". `load_config` 는 봇 주기마다 불리므로 '설정됨 → 미설정'으로 바뀔 때 한 번만 남긴다(프로세스 메모리 플래그, 재시작하면 다시 한 번).

- 운영 영향: 설정 파일에 비어 있지 않은 해시가 있으면 `load_config` 는 파일 해시를 쓰고(`.env` 값보다 우선, 기존과 같음), 이번 변경은 그 경로를 건드리지 않는다. 운영 S9 처럼 기본값이 아닌 해시가 저장돼 있으면 로그인 동작은 바뀌지 않는다.

### P2. M3 의 "해시를 비우면 기본 비밀번호로 열린다" 경고 갱신 (M3 정정)
- M3 은 "해시가 비어 있으면 … `.env` 에 그 키가 없으면 코드의 기본 비밀번호로 대체한다. 이 경우 admin 화면이 기본 비밀번호로 열린다"고 했다. P1 이후에는 **열리지 않고 로그인 불가가 된다**(`.env` 에 `VWAP_ADMIN_PASSWORD` 가 있으면 그 비밀번호로만 열린다).

- M3 마지막 문장("비밀번호가 기본값이 아닌지 … 배포 전에 확인")은 새 코드에서는 "해시가 비어 있지 않거나 `.env` 에 `VWAP_ADMIN_PASSWORD` 가 있는지 배포 전에 확인(없으면 로그인 불가)"으로 읽는다.

- 이유: 메인 대시보드와 SRT 화면은 로그인 없이 보고 싶고, 대기열 조회는 여행 일정이 드러나므로 로그인을 요구한다.
- `/system_status` 반환값은 배터리(%·온도·상태), RAM, CPU, 저장공간, 갱신 시각, 최근 추이뿐이다. 호스트명·경로·IP 는 없다.
- `@page_login_required` 는 지금 쓰이는 라우트가 없지만 `api/auth.py` 에 재사용용으로 남긴다. 되돌리려면 `/`, `/trains` 에 다시 붙인다.
- 토큰은 여전히 어떤 HTML 에도 넣지 않는다(공개 페이지가 늘었으므로 더 중요). 공개 페이지에서 SRT 대기열 영역은 401 을 받으므로 화면은 로그인 안내를 보여야 한다(UI 후속).
- 회귀 테스트: `scripts/test_auth_boundary.py` A3·A6·A9 를 새 정책으로 수정.

### 정정 메모 P5 (2026-10-08, D9 전역 슬롯 선점 완화 — 본문·m3 는 수정하지 않음)

- 문제(m3 에서 인정한 한계): 전역 제한 중 30초 슬롯을 공격자 요청이 먼저 가져가면 소유자 로그인이 계속 429 로 밀린다.
- 결정: **이 프로세스에서 로그인에 성공한 적 있는 클라이언트 키(신뢰 키)는 전역 제한 중에도 슬롯을 기다리지 않고 검사받는다.** 신뢰 키 검사는 공용 슬롯을 소비하지 않고(다른 키의 30초 간격 계산에 영향 없음), 실패는 그대로 키별·전역 실패 수에 들어간다. 키별 잠금(10분 5회 → 15분)은 신뢰 키에도 똑같이 적용되며, 잠기면 신뢰를 회수한다. 신뢰 키는 프로세스 메모리에만 두고(D9 보관 원칙 그대로) 최대 20개, 마지막 성공 후 30일까지 유효하다. 재시작하면 비워진다.
- 근거: 신뢰는 올바른 비밀번호로만 생기므로 공격자가 스스로 만들 수 없다. 공격자가 소유자 IP 를 공유하거나(통신사 NAT 등) 알아내도 그 키로 얻는 추가 검사는 키별 잠금 한도(15분 5회)를 넘지 못한다. `Cf-Connecting-IP` 는 Cloudflare 가 덮어쓰므로 터널을 통해 위조할 수 없다(R14).
- 기각: "실패 기록이 없는 키 우선" — 위조·분산 키는 모두 실패 기록이 없는 새 키이므로 공격자도 똑같이 우대받는다. 신뢰 키 영구 보관(파일) — R13 과 같은 이유(디스크 쓰기, 손상 처리)로 기각.
- 남는 한계: 처음 보는 IP(새 기기, 재시작 직후, IP 변경)에서는 여전히 m3 의 지연이 있다. 이때는 m3 의 우회 경로(`ssh -L` 직접 접속, `pm2 restart butler`)를 쓴다.
- 코드: `api/login_throttle.py`(`TRUSTED_TTL`, `TRUSTED_MAX`, `_trusted`), 테스트: `scripts/test_login_priority_and_mode.py` L1~L4.
