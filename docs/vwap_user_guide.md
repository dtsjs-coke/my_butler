# LIMIT VWAP Trading Bot 사용자 가이드 (User Manual)

본 문서는 LIMIT VWAP 자동 매매 시스템의 핵심 로직, 매매 파라미터의 상세 정의, 그리고 실전 투자 고수들이 활용하는 대표적인 설정값 가이드를 설명합니다.

---

## 1. LIMIT VWAP 전략 핵심 요약

본 자동 매매 봇은 당일 리셋 시각부터 누적으로 **VWAP(거래량 가중 평균 가격)**을 실시간 연산하고, 이 VWAP 라인을 기준선 삼아 철저히 **지정가(Limit) 주문**을 제출하고 제어합니다.

### 📈 매매 규칙 개요
1. **진입 (지정가 매수)**:
   * 현재가가 VWAP 선보다 아래에 위치하고 보유 주식이 없을 때 작동합니다.
   * 실시간으로 **매수 타겟 가격**($TargetBuy = VWAP \times (1 - N\%)$)을 계산하여 **지정가 매수** 주문을 제출합니다. VWAP 선의 변동에 맞춰 미체결 매수 주문은 취소 및 재접수(Cancel & Replace)를 반복하며 실시간 추종합니다.
2. **청산 (지정가 매도)**:
   * 주식을 보유하고 있을 때 작동합니다.
   * 현재가가 VWAP 선을 다시 상향 돌파하거나, **매도 타겟 가격**($TargetSell = VWAP \times (1 + M\%)$) 이상 상승 시 **지정가 매도** 주문이 집행되거나 청산됩니다.
3. **손절 (Stop Loss)**:
   * 주식 평단가 대비 가격이 $-X\%$ 이하로 하락 시, 즉시 미체결 매도 주문을 취소하고 **시장가(Market)로 전량 즉시 청산**하여 추가 손실을 방지합니다.

## 2. 다중 가상 자동매매 및 종합 잔고

가상 자동매매의 경우 최대 3개의 개별 봇 인스턴스(**VIRTUAL_1, VIRTUAL_2, VIRTUAL_3**)를 동시에 구동할 수 있습니다.

* **가상거래 종합 잔고 현황**: 3개 가상 봇의 가용 현금과 주식 평가금을 합산하여 전체 총자산 및 누적 수익률(ROI), 합산 승률을 실시간 요약 표기합니다.
* **서브 탭 스위칭**: 대시보드의 `🤖 가상 봇 1` ~ `🤖 가상 봇 3` 단추를 누르면, 설정 화면, 차트 위젯, 주문 현황, 체결 이력, 터미널 로그가 해당 가상 봇의 정보로 즉시 전환됩니다.
* **실거래 듀얼 수익률 표기**: 실제 거래 연동 시 대시보드는 **TOSS 계좌 전체** 현황과 **VWAP 봇 전용** 성과를 듀얼 모드로 동시에 제공합니다.
  * *TOSS 계좌 전체*: 연동된 토스증권 계좌 내의 모든 주식 평가금과 예수금을 합산하여 '기준 자본금' 대비 ROI를 보여줍니다.
  * *VWAP 봇 전용*: 봇의 실제 주문 체결 이력(`vwap_trades_real.json`)의 누적 실현 손익과 봇이 가동 중인 종목의 평가 손익만을 취합하여 '기준 자본금' 대비 ROI를 독립적으로 산출합니다. 계좌 내 타 종목이나 수동 거래 건은 봇 수익률에서 자동 제외되어 알고리즘 자체의 객관적인 성과를 측정하기에 매우 적합합니다.

## 4. 보조 지표 및 Dev Band 작동 방식

### 📊 RSI 및 ADX 필터 (사용자 직접 지정 방식)
RSI와 ADX 보조 지표를 활용하여 추세가 너무 강한 급락장에서 매수했다가 물리는 리스크를 2차 차단합니다.
* **ADX 필터 (대표값: 25~30)**: ADX 수치가 25~30 이상으로 매우 높다면 강력한 원웨이(One-way) 추세장이 진행 중임을 의미합니다. 이때는 이격이 발생해도 진입을 자동 보류(WAIT)하여 급락장에 칼날을 잡는 현상을 방지합니다.
* **RSI 필터 (대표값: 30~35)**: RSI가 30~35 이하로 충분히 과매도 권역에 도달했을 때에만 지정가 매수를 제출하도록 제한하여 진입 단가의 안전성을 높입니다.

### 📐 Dev Band (표준편차 밴드 자동 연산 방식)
* 사용자가 대시보드에서 `Dev Band` 체크박스를 체크하면, 고정 퍼센트 이격률(`N%`, `M%`)을 적용하는 대신 **볼린저 밴드와 유사한 통계적 변동성 적응 밴드**가 활성화됩니다.
* 봇은 실시간 캔들의 거래량 가중 표준편차의 **2.0배수(2.0 시그마)** 밴드 폭을 매수/매도 타겟으로 스스로 연산합니다. 
* 통계적으로 가격이 2시그마 밴드를 일시적으로 벗어났다가 회귀할 확률이 약 **95.4%**에 달하므로, 변동성이 수시로 변하는 개별 잡주 매매 시 이 값을 활성화하면 가격 변동성에 맞추어 타겟가가 자동 조절되어 매우 유리합니다. (사용자는 수치를 입력할 필요 없이 체크박스만 켜시면 됩니다.)

## 5. 금융 안전장치 및 미수 방지 정책

1. **순수 현금(Cash) 기반 예산 검증**: 봇은 매수 주문 전 예수금 상태를 이중 점검하여 주문 예정 총액이 보유 현금을 초과할 경우 진입을 제한하거나 수량을 자동 축소해 미수금 발생 위험을 방지합니다.
2. **현금 100% 매수 주문 보장**: 토스증권 API 호출 시 신용융자가 불가능한 **현금 주문(CASH)** 형태를 강제함으로써 미수/신용 거래 위험을 원천 무력화합니다.
3. **당일 손실 한도 초과 시 시스템 강제 중지**: 세션 기준 자산 대비 손실이 설정된 일 최대 손실한도(예: -5%)를 돌파하면 봇 스스로 미체결 주문을 취소하고 보유 주식을 전량 시장가로 매도(Panic Sell)한 뒤 봇 작동을 정지(STOP)시킵니다.
   * **기준 변경 (2026-10-05)**: 세션 날짜는 달력 날짜가 아니라 VWAP 리셋 시각 기준입니다(미국장 22:30 리셋이면 자정을 넘겨도 같은 세션). 실거래(REAL)는 `기준 자본금 + 봇 누적 실현손익 + 봇 종목 평가손익`을 기준 자산으로 삼으므로, 계좌의 다른 종목이나 입출금은 한도 판정에 영향을 주지 않습니다.
4. **손절/패닉 청산 재시도**: 손절·패닉 시 먼저 미체결 주문의 **취소 완료를 확인**한 뒤 시장가 매도를 냅니다. 실제 잔고를 다시 조회해 청산 수량을 보정하며, 실패하면 **최대 3회까지 재시도**합니다. 패닉 청산이 3회 모두 실패하면 봇을 **정지**하고 로그에 `CRITICAL`을 남기므로 **즉시 토스 앱에서 직접 확인·청산**해야 합니다.
5. **거래 시작 시각 대기 중에도 손절 유지 (2026-10-07)**: 거래 시작 시각 전 대기 구간에서도 보유 주식이 손절가를 깨면 즉시 시장가로 손절합니다. 대기 중에 막는 것은 신규 매수뿐입니다(9장).
6. **미체결 조회 실패 시 보수적 동작**: 미체결 주문 목록을 가져오지 못한 주기에는 신규 매수/정정만 보류하고, 손절은 그대로 진행합니다(중복 주문 방지 + 손절 지연 방지).
7. **체결 기록 방식 (실거래)**: 주문 상세 조회로 체결/취소/부분체결을 판정하고 **실제 체결가·수량·수수료**를 `vwap_trades_real.json`에 기록합니다. 각 기록의 `fill_source`는 근거를 뜻합니다.
   * `order_api`: 토스 주문 상세 조회로 확인된 값(가장 신뢰).
   * `holdings_diff`: 상세 조회 실패 시 보유 수량 변화로 교차 검증한 값.
   * `assumed`: 주문은 접수됐으나 체결 조회가 불가해 봉 종가로 **가정**한 값(시장가 청산 등) — 토스 체결내역과 대조 권장.
   * 3회 연속 판정 불가이면 기록하지 않고 `ERROR` 로그를 남깁니다. 추적 중인 주문은 `data/vwap_tracked_orders_real.json`에 저장되어 재시작 후에도 이어집니다.
8. **거래기록 파일 보호**: 거래기록은 원자적으로 저장되며, 파일이 손상된 경우 `.corrupt-<타임스탬프>` 파일로 보존하고 `[거래기록 파일]` `ERROR` 로그를 남깁니다.
9. **가상봇 체결 정상화**: 이전에는 가상봇(VIRTUAL_1~3)이 모드 판정 버그로 체결이 전혀 되지 않았습니다. 수정 후 처음으로 실제 가상 매매가 이뤄지므로 과거와 성과가 다르게 보일 수 있습니다.

### 백테스트 한계
대시보드 백테스트는 **최근 캔들 150개(1분봉 기준 약 2.5시간)** 로만 계산하며(실제 봇은 2026-10-06부터 세션 시작부터의 봉을 씁니다 — 8장) **수수료를 반영하지 않는 참고용**입니다. 실거래 성과를 보장하지 않습니다. 입력 오류는 400, 시세 서버 응답 오류는 502, 그 외 서버 오류는 500과 함께 한글 사유가 화면에 표시됩니다. 종목코드가 6자리 숫자면 ₩, 아니면 $로 표기합니다.

## 6. 토스 실거래 듀얼 자산/수익률(ROI) 표기 가이드

실제 거래 대시보드에서는 사용자의 혼선을 줄이고 알고리즘 봇의 독립적인 성과 분석을 위해 **듀얼 모드 표기(Dual Display)**를 적용하고 있습니다.

1. **🏦 TOSS 계좌 전체**:
   * 토스증권 API를 통해 계좌 내 보유한 모든 예수금과 주식 평가금액을 실시간 합산하여 계좌 전체의 총자산을 요약합니다.
   * 계좌 전체 ROI는 `(계좌 총자산 - 설정 자본금) / 설정 자본금 * 100`으로 계산됩니다. 이는 사용자가 계좌 내에서 수동으로 거래하는 종목들의 평가금이 모두 포함된 값입니다.
2. **🤖 VWAP 봇 성과**:
   * 알고리즘 봇이 거래한 순수 내역과 봇이 보유 중인 타겟 종목만을 추적하여 격리 분석한 성과를 제공합니다.
   * **누적 실현 손익 (Realized PnL)**: `vwap_trades_real.json` 파일에 저장된 봇의 과거 체결 완료(매도 청산) 내역의 실현 손익 합산.
   * **현재 평가 손익 (Unrealized PnL)**: 봇이 현재 매매 대상 종목(`real_ticker`, 예: AAPL)을 보유 중일 때, 현재가와 매수 평단가의 이격으로 발생하는 평가 손익.
   * **봇 전용 누적 손익**: `봇 누적 실현 손익 + 봇 현재 평가 손익`
   * **봇 전용 ROI (%)**: `봇 전용 누적 손익 / 기준 자본금 * 100`

이러한 분리 기법을 통해, 단일 계좌 내에서 수동 투자를 병행하더라도 봇의 전략 성과(수익률, 승률)를 완벽하게 격리하여 모니터링할 수 있습니다.

## 7. 봇이 "왜 주문했/안 했는지" 확인하기 (관측성, 2026-10-05 추가)

매매 동작은 그대로이고, **판단 사유·이벤트 기록·알림**만 추가되었습니다.

### 판단 사유 (`reason_code` / `reason_text`)
대시보드 상태(`/vwap/api/status`의 각 봇 객체)에 이번 주기의 판단 사유가 한 문장으로 표시됩니다.

| 코드 | 의미 |
|---|---|
| `ABOVE_VWAP` | 무포지션, 현재가가 VWAP 이상 → 매수 대기 |
| `BUY_ARMED` | 현재가가 VWAP 아래 → 매수 지정가 걸어둠 |
| `FILTER_ADX` / `FILTER_RSI` | 가격 조건은 맞지만 ADX(강한 추세)·RSI(과매도 아님) 필터가 진입을 막음 |
| `HOLD` | 보유 중, VWAP 아래라 청산 대기 (손절가 표시) |
| `SELL_ARMED` | VWAP 상향 돌파(또는 매도 타겟 도달) → 매도 지정가 걸어둠 |
| `STOP_LOSS` | 손절가 이탈 → 시장가 손절 |
| `WAIT_START_TIME` | 거래 시작 시각 이전 + 보유 주식 없음 → 신규 매수 대기 (보유 중이면 이 코드 대신 `STOP_LOSS`·`SELL_ARMED`·`HOLD` 가 그대로 표시됨) |
| `BUDGET_SHORT` | 투자 예산이 1주 가격보다 작아 매수 보류 |
| `DAILY_LOSS_STOP` | 당일 손실 한도 초과 → 패닉 청산 후 정지 |
| `DATA_UNAVAILABLE` | 캔들/잔고/미체결 조회 실패로 이번 주기 보류 |
| `LOOP_ERROR` | 주기 실행 중 예외로 이번 주기 보류 |
| `BOT_STOPPED` | 봇 정지 상태 (자동 정지면 사유 문장에 이유 표시) |

`filters`에는 ADX/RSI 필터의 켜짐 여부·현재값·기준값·`blocking`(현재 값이면 신규 매수를 막는지)이 함께 나옵니다.

### 이벤트 로그
* 파일: `data/vwap_events_{real|virtual_1|virtual_2|virtual_3}.jsonl` (한 줄 = 이벤트 1건). 2MB를 넘으면 `.1`로 한 번 회전합니다(최대 약 4MB).
* 종류: `BOT_START`, `BOT_STOP`, `SIGNAL_CHANGE`(판단이 바뀔 때만), `ORDER_PLACED`, `ORDER_REPLACED`, `ORDER_CANCELED`, `FILL`, `STOP_LOSS`, `PANIC`, `ERROR`, `CRITICAL`.
* 조회 API: `GET /vwap/api/events?mode=REAL&limit=100&types=FILL,STOP_LOSS` (로그인 필요, 최신순, 최대 500건).

### 거래기록 추가 필드
`slippage`(체결가와 의도한 가격의 차이, **불리하면 +**: 매수는 `체결가-의도가`, 매도/손절은 `의도가-체결가`. 의도가는 지정가면 주문가, 시장가 청산이면 결정 시점 현재가), `slippage_pct`, `holding_minutes`(매도/손절 시 포지션 진입부터의 분), `reason_code`·`filters`·`config_snapshot`(주문 당시 판단/설정), `intended_price`. 기존 필드는 그대로입니다.

### Discord 알림
* 기존 Butler 알림 경로(상태 채널, `STATUS_CHANNEL_ID`)로 보냅니다. 실거래는 `ORDER_PLACED`, `FILL`, `STOP_LOSS`, `PANIC`, `CRITICAL`, 5주기 연속 조회 실패(`ERROR`), `BOT_START/STOP`을 알립니다.
* 설정: `real_discord_notify`(기본 켬), `virtual_discord_notify`(기본 끔, 가상봇 1~3 공통). 같은 종류·사유의 알림은 60초 안에 한 번만 보냅니다(체결은 체결마다 따로).

## 8. VWAP "세션" 기준 변경 (2026-10-06, ADR-0008)

### 한 줄 요약
**VWAP은 이제 "리셋 시각부터 다음 리셋 시각까지" 끊김 없이 쌓입니다.** 미국 종목은 서머타임에 맞춰 리셋 시각이 22:30과 23:30 사이에서 자동으로 바뀝니다.

### 무엇이 문제였나요?
1. **자정에 VWAP이 초기화되던 버그.** 미국장은 한국 시간 밤 22:30에 열려 새벽 05:00에 닫힙니다(서머타임 기준). 그런데 봇은 날짜가 바뀌는 **00:00에 VWAP을 처음부터 다시 계산**했습니다. 그래서 장 한가운데에서 VWAP 선·매수/매도 타겟·Dev Band가 갑자기 현재가 쪽으로 튀었습니다.
   예) 23:59 가격 100 → 00:00 가격 106 (거래량 같음): 올바른 VWAP은 **103**이지만 봇은 **106**으로 계산했습니다.
2. **서머타임이 끝나면 리셋 시각이 1시간 어긋나는 문제.** 미국 서머타임은 **2026년 11월 1일(일)** 에 끝납니다. 그 뒤로 미국 정규장은 한국 시간 **23:30**에 열립니다. 리셋이 22:30에 고정돼 있으면 개장 1시간 전(프리마켓)부터 새 세션을 세는 셈이었습니다.
3. **실제로는 최근 2.5시간만 보고 있었던 문제.** 봇은 매번 최근 1분봉 150개(약 2.5시간)만 받아 왔습니다. 그래서 "리셋 시각부터 누적"이라는 설명과 달리, 실제 VWAP은 대부분 "최근 2.5시간 누적"이었습니다.

### 어떻게 바뀌었나요?
| 항목 | 예전 | 지금 |
|---|---|---|
| VWAP이 새로 시작되는 때 | 리셋 시각 **그리고 매일 00:00** | 리셋 시각 **한 번만** |
| 미국 종목 리셋 시각 | 22:30 고정 | 서머타임 중 **22:30**, 서머타임 해제 후 **23:30** (자동) |
| VWAP에 쓰는 봉 | 항상 최근 150개 | **세션 시작부터 지금까지 전부** (최대 1600개) |
| 정규장 밖(프리·애프터·주간거래) 봉 | VWAP에 포함, 매매 가능 | **똑같이 포함, 매매 가능** (바뀌지 않음) |
| 일 손실한도의 "하루" | 리셋 시각 기준 세션 | 같은 세션 기준 (미국 종목은 서머타임 자동 반영) |

- 서머타임 날짜는 미국 규칙(3월 둘째 일요일 ~ 11월 첫째 일요일)으로 봇이 직접 계산합니다.
- 서머타임이 바뀌는 날은 그 세션만 하루가 25시간(11월) 또는 23시간(3월)입니다.

### 사용자가 해야 할 일
- **설정은 바꾸지 않아도 됩니다.** 미국 종목 리셋 시각을 `22:30` 그대로 두면 11월 1일 이후 자동으로 23:30에 리셋됩니다. 11월 1일 전에 S9에 배포되어 있어야 합니다.
- 리셋 시각을 일부러 고정하고 싶다면 22:30/23:30이 아닌 값(예: `21:00`)을 넣으세요. 그 시각을 매일 그대로 씁니다.

### 체감할 수 있는 차이 (꼭 읽어 주세요)
- **VWAP 선이 예전보다 천천히 움직입니다.** 이제 세션 전체(최대 하루치) 거래를 평균하기 때문입니다. 특히 낮 시간(주간거래)이나 새벽(애프터마켓)에는 VWAP이 전날 밤 정규장 가격 쪽에 머무는 경향이 생깁니다.
- 같은 N%/M% 설정이라도 **매수·매도 타겟 위치와 체결 횟수가 예전과 달라질 수 있습니다.** 배포 후 며칠은 가상봇 결과와 판단 사유를 함께 지켜봐 주세요.
- Dev Band(표준편차 밴드)도 세션 전체 기준이라 대체로 폭이 넓어집니다.

### 상태 화면에 추가된 값 (확인용)
- `session_label`: 지금 VWAP 세션 기준과 기간. 예) `미국장 자동(서머타임 22:30 / 표준시 23:30) 10-06 22:30~10-07 22:30 KST`
- `vwap_full_session`: 이번 VWAP이 세션 시작부터의 봉을 모두 포함했으면 `true`입니다. `false`면 시세 서버에서 과거 봉을 다 받지 못해 일부 구간만 누적한 값입니다(예전과 같은 방식이고 매매는 그대로 진행). 이 경우 봇 로그에 `⚠️ VWAP 이 세션 시작(...)부터의 봉을 다 포함하지 못함` 경고가 세션마다 한 번 남습니다.

## 9. "거래 시작 시각" 대기 중에도 손절은 합니다 (2026-10-07, ADR-0009)

### 한 줄 요약
**거래 시작 시각 전에는 "새로 사는 것"만 멈춥니다.** 이미 가지고 있는 주식은 대기 중에도 평소처럼 손절·매도합니다.

### 거래 시작 시각이란?
VWAP 이 새로 시작(리셋)된 직후는 가격이 크게 출렁이고 VWAP 도 몇 개 안 되는 봉으로 계산돼 불안정합니다. 그래서 "리셋 후 조금 기다렸다가 사자"는 설정이 거래 시작 시각입니다.
- 예) 리셋 `22:30`, 거래 시작 `23:30` → 22:30~23:29 는 **대기 구간**, 23:30 부터 정상 매매.
- 비워 두면 대기 없이 리셋 직후부터 바로 매매합니다(현재 운영 설정은 모두 빈 값).

### 무엇이 문제였나요?
예전에는 대기 구간 동안 봇이 **모든 판단을 "대기"로 바꿔 버렸습니다.** 그래서 전날 밤에 사서 들고 있던 주식이 대기 구간에 손절가 아래로 떨어져도 **손절하지 않았고**, 걸어 둔 매도 주문까지 취소했습니다. 대기 구간이 1시간이면 그 1시간 동안 손절 보호가 없었던 것입니다.

### 어떻게 바뀌었나요? (대기 구간 안에서)
| 내 상황 | 예전 | 지금 |
|---|---|---|
| 주식 없음, 가격이 VWAP 아래(평소라면 매수) | 매수 안 함 | 매수 안 함 (같음) |
| 주식 보유, 손절가 아래로 하락 | **손절 안 함**, 미체결 주문 전부 취소 | **즉시 시장가 손절** (평소와 같음) |
| 주식 보유, 가격이 VWAP 위 | 매도 주문도 취소 | **지정가 매도 주문** (평소와 같음) |
| 주식 보유, 그 사이 가격 | 미체결 주문 취소 | 미체결 주문 취소 (평소와 같음) |

- 쉽게 말해 **주식을 갖고 있을 때는 거래 시작 시각 설정이 아무 영향을 주지 않습니다.** 주식이 없을 때만 "아직 사지 말 것"으로 작동합니다.
- 대기 중에 매도하는 주기에는, 혹시 남아 있는 매수 주문(일부만 체결되고 남은 잔량 등)을 먼저 취소합니다. 대기 중에 새로 사게 되는 일을 막기 위해서입니다.
- 일 최대 손실한도(패닉 정지)는 예전과 똑같이 대기와 상관없이 작동합니다.

### 화면에서 보이는 것
- 대기 구간이면 상단에 **"시작 대기"** 표시가 그대로 나옵니다(주식 보유 여부와 관계없이).
- 주식이 없으면 판단 사유가 `WAIT_START_TIME`(거래 시작 시각 이전 → 신규 매수 대기)입니다.
- 주식을 보유 중이면 판단 사유는 평소처럼 `STOP_LOSS`/`SELL_ARMED`/`HOLD` 가 나옵니다.

### 사용자가 해야 할 일
- 없습니다. 현재 설정의 거래 시작 시각은 모두 비어 있어서 배포 후에도 실제 매매에는 당장 차이가 없습니다. 앞으로 거래 시작 시각을 켜더라도 손절 보호가 유지됩니다.
- 리플레이(과거 시뮬레이션)에서 거래 시작 시각을 쓰면, 연구용 백테스트 결과와 "대기 구간 신규 매수"만큼 차이가 날 수 있습니다. 정상입니다.
