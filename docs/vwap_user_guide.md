# LIMIT VWAP Trading Bot 사용자 가이드 (User Manual)

본 문서는 LIMIT VWAP 자동 매매 시스템의 핵심 로직, 매매 파라미터의 상세 정의, 그리고 실전 투자 고수들이 활용하는 대표적인 설정값 가이드를 설명합니다.

---

## 1. LIMIT VWAP 전략 핵심 요약

본 자동 매매 봇은 당일 리셋 시각부터 누적으로 **VWAP(거래량 가중 평균 가격)**을 실시간 연산하고, 이 VWAP 라인을 기준선 삼아 철저히 **지정가(Limit) 주문**을 제출하고 제어합니다.

### 📈 매매 규칙 개요 (2026-10-07 실제 동작 기준으로 정정)

> 대시보드의 **📈 판단 원리** 탭에서 예시 차트로 직접 확인할 수 있습니다.

**VWAP**은 세션 시작(미국 22:30, 서머타임이 끝나면 23:30 자동)부터 `Σ(종가×거래량) ÷ Σ거래량`으로 계산합니다(8장). 봇은 1분마다 "현재가(가장 최근 봉 종가)"를 VWAP·목표가와 비교해 판단합니다.

* **매수 목표가** = $VWAP \times (1 - N\%)$, **매도 목표가** = $VWAP \times (1 + M\%)$, **손절가** = $평단 \times (1 - X\%)$
* Dev Band를 켜면 N%/M% 대신 `VWAP ∓ σ × 거래량가중표준편차`가 목표가가 됩니다(4장).

1. **진입 (지정가 매수)** — 주식이 없을 때:
   * 현재가가 **VWAP 아래로 내려오면** 그 순간 **매수 목표가(VWAP − N%)에 지정가 매수 주문을 미리 걸어 둡니다.** 가격이 거기까지 더 떨어져야 체결됩니다(현재가에 바로 사는 것이 아닙니다).
   * 현재가가 VWAP 이상이면 주문 없이 대기(WAIT)합니다.
   * 목표가가 0.01 넘게 바뀌거나 수량이 바뀌면 기존 주문을 취소하고 다시 겁니다(Cancel & Replace, 1분마다).
   * ADX/RSI 필터가 켜져 있으면 조건을 통과할 때만 매수 주문을 겁니다(4장). 거래 시작 시각 전이면 신규 매수만 대기합니다(9장).
2. **청산 (지정가 매도)** — 주식을 보유 중일 때:
   * 현재가가 VWAP 이상이 되거나 매도 목표가 이상이 되면, **매도 목표가(VWAP + M%)에 지정가 매도 주문**을 걸어 둡니다. VWAP을 돌파한 그 가격에 파는 것이 아니라 **VWAP + M%** 에 걸어 둡니다.
   * **매도 주문을 건 뒤 가격이 다시 VWAP 아래로 내려가면 그 매도 주문은 취소**되고(HOLD), 다시 올라오면 새로 겁니다.
   * 매도에는 ADX/RSI 필터가 관여하지 않습니다.
3. **손절 (Stop Loss)** — 주식을 보유 중일 때 가장 먼저 검사합니다:
   * 현재가가 손절가(평단 − X%) 이하이면 미체결 주문의 **취소 완료를 확인한 뒤 시장가로 전량 매도**합니다. 청산·매도 판단보다 항상 우선합니다.
4. **대기(HOLD/WAIT)**: 위 어디에도 해당하지 않으면 **걸려 있던 미체결 주문을 모두 취소**합니다.
5. **주문 수량**: (기준 자본금 × K%) ÷ 매수 목표가를 정수로 내림합니다. 기준 자본금이 0이면 실제 현금을 씁니다. 현금을 넘으면 현금으로 제한하고, 1주도 못 사면 `BUDGET_SHORT`(7장)로 보류합니다.
6. **판단 전 점검 순서**: 시세 수신 → (실거래) 시세 출처 신뢰(10장) → 잔고·미체결 조회 → 일 손실한도 → 신호 → 주문.

## 2. 다중 가상 자동매매 및 종합 잔고

가상 자동매매의 경우 최대 3개의 개별 봇 인스턴스(**VIRTUAL_1, VIRTUAL_2, VIRTUAL_3**)를 동시에 구동할 수 있습니다.

* **가상거래 종합 잔고 현황**: 3개 가상 봇의 가용 현금과 주식 평가금을 합산하여 전체 총자산 및 누적 수익률(ROI), 합산 승률을 실시간 요약 표기합니다.
* **서브 탭 스위칭**: 대시보드의 `🤖 가상 봇 1` ~ `🤖 가상 봇 3` 단추를 누르면, 설정 화면, 차트 위젯, 주문 현황, 체결 이력, 터미널 로그가 해당 가상 봇의 정보로 즉시 전환됩니다.
* **실거래 듀얼 수익률 표기**: 실제 거래 연동 시 대시보드는 **TOSS 계좌 전체** 현황과 **VWAP 봇 전용** 성과를 듀얼 모드로 동시에 제공합니다.
  * *TOSS 계좌 전체*: 연동된 토스증권 계좌 내의 모든 주식 평가금과 예수금을 합산하여 '기준 자본금' 대비 ROI를 보여줍니다.
  * *VWAP 봇 전용*: 봇의 실제 주문 체결 이력(`vwap_trades_real.json`)의 누적 실현 손익과 봇이 가동 중인 종목의 평가 손익만을 취합하여 '기준 자본금' 대비 ROI를 독립적으로 산출합니다. 계좌 내 타 종목이나 수동 거래 건은 봇 수익률에서 자동 제외되어 알고리즘 자체의 객관적인 성과를 측정하기에 매우 적합합니다.

## 4. 보조 지표 및 Dev Band 작동 방식 *(2026-10-07 실제 동작 기준으로 정정)*

### 📊 RSI 및 ADX 필터 (사용자 직접 지정 방식)
RSI와 ADX 보조 지표를 활용하여 추세가 너무 강한 급락장에서 매수했다가 물리는 리스크를 2차 차단합니다. 두 지표 모두 **14봉 기준**으로 계산합니다.
* **적용 범위: 신규 매수에만 적용됩니다.** 매도와 손절에는 관여하지 않습니다.
* **ADX 필터 (기본 25, 대표값: 25~30)**: ADX가 기준 **이상**이면 강력한 원웨이(One-way) 추세장이 진행 중이라고 보고, VWAP 아래여도 매수를 보류(WAIT)합니다.
* **RSI 필터 (기본 30, 대표값: 30~35)**: RSI가 기준 **이하**일 때만 매수합니다. 기준보다 높으면(과매도가 아니면) 보류(WAIT)합니다.
* **둘 다 켜면 AND 조건**입니다. 두 조건을 모두 통과해야 매수 주문을 겁니다(하나라도 막으면 WAIT).
* **필터가 막으면 이미 걸어 둔 매수 주문도 취소됩니다.** 필터가 매수를 막는 순간 신호가 WAIT가 되어, 그전에 걸어 둔 미체결 매수 주문이 정리됩니다(1장 4번).
* 막힌 이유는 사유 코드 `FILTER_ADX` / `FILTER_RSI` 로 표시됩니다(7장 참조).

### 📐 Dev Band (표준편차 밴드 자동 연산 방식)
* 사용자가 대시보드에서 `Dev Band` 체크박스를 체크하면, 고정 퍼센트 이격률(`N%`, `M%`) 대신 **볼린저 밴드와 비슷한 변동성 적응 밴드**로 목표가를 계산합니다.
* 매수 목표가 = `VWAP − σ × 거래량가중표준편차`, 매도 목표가 = `VWAP + σ × 거래량가중표준편차`. **σ(시그마 배수)는 대시보드에서 입력합니다(기본 2.0).**
* 표준편차는 세션 시작부터의 값이라(8장) 변동성이 큰 종목일수록 밴드가 넓어져 목표가가 자동으로 멀어집니다.
* 참고: 2σ는 가격이 정규분포를 따른다고 가정했을 때 약 95%가 밴드 안에 들어온다는 뜻일 뿐, 밴드 밖으로 나간 가격이 **되돌아올 확률**을 말하는 것이 아닙니다. 되돌림은 보장되지 않습니다.

## 5. 금융 안전장치 및 미수 방지 정책

1. **순수 현금(Cash) 기반 예산 검증**: 봇은 매수 주문 전 예수금 상태를 이중 점검하여 주문 예정 총액이 보유 현금을 초과할 경우 진입을 제한하거나 수량을 자동 축소해 미수금 발생 위험을 방지합니다.
2. **현금 100% 매수 주문 보장**: 토스증권 API 호출 시 신용융자가 불가능한 **현금 주문(CASH)** 형태를 강제함으로써 미수/신용 거래 위험을 원천 무력화합니다.
3. **당일 손실 한도 초과 시 시스템 강제 중지**: 세션 기준 자산 대비 손실이 설정된 일 최대 손실한도(예: -5%)를 돌파하면 봇 스스로 미체결 주문을 취소하고 보유 주식을 전량 시장가로 매도(Panic Sell)한 뒤 봇 작동을 정지(STOP)시킵니다.
   * **기준 변경 (2026-10-05)**: 세션 날짜는 달력 날짜가 아니라 VWAP 리셋 시각 기준입니다(미국장 22:30 리셋이면 자정을 넘겨도 같은 세션). 실거래(REAL)는 `기준 자본금 + 봇 누적 실현손익 + 봇 종목 평가손익`을 기준 자산으로 삼으므로, 계좌의 다른 종목이나 입출금은 한도 판정에 영향을 주지 않습니다.
4. **손절/패닉 청산 재시도**: 손절·패닉 시 먼저 미체결 주문의 **취소 완료를 확인**한 뒤 시장가 매도를 냅니다. 실제 잔고를 다시 조회해 청산 수량을 보정하며, 실패하면 **최대 3회까지 재시도**합니다. 패닉 청산이 3회 모두 실패하면 봇을 **정지**하고 로그에 `CRITICAL`을 남기므로 **즉시 토스 앱에서 직접 확인·청산**해야 합니다.
5. **거래 시작 시각 대기 중에도 손절 유지 (2026-10-07)**: 거래 시작 시각 전 대기 구간에서도 보유 주식이 손절가를 깨면 즉시 시장가로 손절합니다. 대기 중에 막는 것은 신규 매수뿐입니다(9장).
6. **미체결 조회 실패 시 보수적 동작**: 미체결 주문 목록을 가져오지 못한 주기에는 신규 매수/정정만 보류하고, 손절은 그대로 진행합니다(중복 주문 방지 + 손절 지연 방지).
7. **체결 기록 방식 (실거래)**: 주문 상세 조회로 체결/취소/부분체결을 판정하고 **실제 체결가·수량·수수료**를 `vwap_trades_real.json`에 기록합니다. 각 기록의 `fill_source`는 근거를 뜻합니다.
   * `order_api`: 토스 주문 상세 조회로 확인된 값(가장 신뢰).
   * `holdings_diff`: 상세 조회 실패 시 보유 수량 변화로 교차 검증한 값.
   * `assumed`: 주문은 접수됐으나 체결 조회가 불가해 봉 종가로 **가정**한 값(시장가 청산 등) — 토스 체결내역과 대조 권장.
   * 3회 연속 판정 불가이면 기록하지 않고 `ERROR` 로그를 남깁니다. 추적 중인 주문은 `data/vwap_tracked_orders_real.json`에 저장되어 재시작 후에도 이어집니다.
8. **거래기록 파일 보호**: 거래기록은 원자적으로 저장되며, 파일이 손상된 경우 `.corrupt-<타임스탬프>` 파일로 보존하고 `[거래기록 파일]` `ERROR` 로그를 남깁니다.
9. **가상봇 체결 정상화**: 이전에는 가상봇(VIRTUAL_1~3)이 모드 판정 버그로 체결이 전혀 되지 않았습니다. 수정 후 처음으로 실제 가상 매매가 이뤄지므로 과거와 성과가 다르게 보일 수 있습니다.

### 백테스트 한계
대시보드 백테스트는 **최근 캔들 150개(1분봉 기준 약 2.5시간)** 로만 계산하며(실제 봇은 2026-10-06부터 세션 시작부터의 봉을 씁니다 — 8장) **수수료를 반영하지 않는 참고용**입니다. 실거래 성과를 보장하지 않습니다. 입력 오류는 400, 시세 서버 응답 오류는 502, 그 외 서버 오류는 500과 함께 한글 사유가 화면에 표시됩니다. 종목코드가 6자리 숫자면 ₩, 아니면 $로 표기합니다.

## 6. 토스 실거래 듀얼 자산/수익률(ROI) 표기 가이드

실제 거래 대시보드에서는 사용자의 혼선을 줄이고 알고리즘 봇의 독립적인 성과 분석을 위해 **듀얼 모드 표기(Dual Display)**를 적용하고 있습니다.

1. **🏦 TOSS 계좌 전체**:
   * 토스증권 API를 통해 계좌 내 보유한 모든 예수금과 주식 평가금액을 실시간 합산하여 계좌 전체의 총자산을 요약합니다.
   * 계좌 전체 ROI는 `(계좌 총자산 - 설정 자본금) / 설정 자본금 * 100`으로 계산됩니다. 이는 사용자가 계좌 내에서 수동으로 거래하는 종목들의 평가금이 모두 포함된 값입니다.
2. **🤖 VWAP 봇 성과**:
   * 알고리즘 봇이 거래한 순수 내역과 봇이 보유 중인 타겟 종목만을 추적하여 격리 분석한 성과를 제공합니다.
   * **누적 실현 손익 (Realized PnL)**: `vwap_trades_real.json` 파일에 저장된 봇의 과거 체결 완료(매도 청산) 내역의 실현 손익 합산.
   * **현재 평가 손익 (Unrealized PnL)**: 봇이 현재 매매 대상 종목(`real_ticker`, 예: AAPL)을 보유 중일 때, 현재가와 매수 평단가의 이격으로 발생하는 평가 손익.
   * **봇 전용 누적 손익**: `봇 누적 실현 손익 + 봇 현재 평가 손익`
   * **봇 전용 ROI (%)**: `봇 전용 누적 손익 / 기준 자본금 * 100`

이러한 분리 기법을 통해, 단일 계좌 내에서 수동 투자를 병행하더라도 봇의 전략 성과(수익률, 승률)를 완벽하게 격리하여 모니터링할 수 있습니다.

## 7. 봇이 "왜 주문했/안 했는지" 확인하기 (관측성, 2026-10-05 추가)

매매 동작은 그대로이고, **판단 사유·이벤트 기록·알림**만 추가되었습니다.

### 판단 사유 (`reason_code` / `reason_text`)
대시보드 상태(`/vwap/api/status`의 각 봇 객체)에 이번 주기의 판단 사유가 한 문장으로 표시됩니다.

| 코드 | 의미 |
|---|---|
| `ABOVE_VWAP` | 무포지션, 현재가가 VWAP 이상 → 매수 대기 |
| `BUY_ARMED` | 현재가가 VWAP 아래 → 매수 지정가 걸어둠 |
| `FILTER_ADX` / `FILTER_RSI` | 가격 조건은 맞지만 ADX(강한 추세)·RSI(과매도 아님) 필터가 진입을 막음 |
| `HOLD` | 보유 중, VWAP 아래라 청산 대기 (손절가 표시) |
| `SELL_ARMED` | VWAP 상향 돌파(또는 매도 타겟 도달) → 매도 지정가 걸어둠 |
| `STOP_LOSS` | 손절가 이탈 → 시장가 손절 |
| `WAIT_START_TIME` | 거래 시작 시각 이전 + 보유 주식 없음 → 신규 매수 대기 (보유 중이면 이 코드 대신 `STOP_LOSS`·`SELL_ARMED`·`HOLD` 가 그대로 표시됨) |
| `BUDGET_SHORT` | 투자 예산이 1주 가격보다 작아 매수 보류 |
| `DAILY_LOSS_STOP` | 당일 손실 한도 초과 → 패닉 청산 후 정지 |
| `DATA_UNAVAILABLE` | 캔들/잔고/미체결 조회 실패로 이번 주기 보류 |
| `LOOP_ERROR` | 주기 실행 중 예외로 이번 주기 보류 |
| `DATA_UNTRUSTED` | (실거래 전용) 시세가 진짜인지 믿을 수 없어 이번 주기 매매 판단 전체 보류 — 9장 다음 10장 참고 |
| `BOT_STOPPED` | 봇 정지 상태 (자동 정지면 사유 문장에 이유 표시) |

`filters`에는 ADX/RSI 필터의 켜짐 여부·현재값·기준값·`blocking`(현재 값이면 신규 매수를 막는지)이 함께 나옵니다.

### 이벤트 로그
* 파일: `data/vwap_events_{real|virtual_1|virtual_2|virtual_3}.jsonl` (한 줄 = 이벤트 1건). 2MB를 넘으면 `.1`로 한 번 회전합니다(최대 약 4MB).
* 종류: `BOT_START`, `BOT_STOP`, `SIGNAL_CHANGE`(판단이 바뀔 때만), `ORDER_PLACED`, `ORDER_REPLACED`, `ORDER_CANCELED`, `FILL`, `STOP_LOSS`, `PANIC`, `ERROR`, `CRITICAL`.
* 조회 API: `GET /vwap/api/events?mode=REAL&limit=100&types=FILL,STOP_LOSS` (로그인 필요, 최신순, 최대 500건).

### 거래기록 추가 필드
`slippage`(체결가와 의도한 가격의 차이, **불리하면 +**: 매수는 `체결가-의도가`, 매도/손절은 `의도가-체결가`. 의도가는 지정가면 주문가, 시장가 청산이면 결정 시점 현재가), `slippage_pct`, `holding_minutes`(매도/손절 시 포지션 진입부터의 분), `reason_code`·`filters`·`config_snapshot`(주문 당시 판단/설정), `intended_price`. 기존 필드는 그대로입니다.

### Discord 알림
* **어느 채널로 가나요?** VWAP 알림은 **VWAP 전용 채널(`VWAP_CHANNEL_ID`)** 로 갑니다. 이 값을 설정하지 않았거나 `0`이면 예전처럼 서버 상태 공지 채널(`STATUS_CHANNEL_ID`)로 갑니다. 그래서 설정을 깜빡해도 알림이 사라지지는 않습니다.
* **설정 방법(초보자용)**: ① Discord에서 VWAP 알림을 받을 채널을 만들고, 채널을 우클릭 → "채널 ID 복사"를 합니다(설정 > 고급 > 개발자 모드가 켜져 있어야 보입니다). ② S9의 `my_butler` 폴더 안 `.env` 파일에 `VWAP_CHANNEL_ID=복사한숫자` 한 줄을 추가합니다. ③ 봇을 재시작합니다(`pm2 restart butler`). 재시작해야 새 값이 적용됩니다. 채널 ID는 비밀번호가 아니지만, 이 문서에는 적지 않습니다.
* 알림 전송은 기존 Butler 알림 경로를 그대로 사용하며, 채널만 위와 같이 정해집니다. 실거래는 `ORDER_PLACED`, `FILL`, `STOP_LOSS`, `PANIC`, `CRITICAL`, 5주기 연속 조회 실패(`ERROR`), 시세 신뢰 불가(`ERROR` — 신뢰 불가 구간이 새로 시작될 때마다. 단 10분 안에 반복되면 묶어서 요약, 3주기 계속되면 `CRITICAL`, 그 뒤에도 계속되면 30분마다 `CRITICAL` 재알림 — 10장), `BOT_START/STOP`을 알립니다.
* 설정: `real_discord_notify`(기본 켬), `virtual_discord_notify`(기본 끔, 가상봇 1~3 공통). 같은 종류·사유의 알림은 60초 안에 한 번만 보냅니다(체결은 체결마다 따로).

## 8. VWAP "세션" 기준 변경 (2026-10-06, ADR-0008)

### 한 줄 요약
**VWAP은 이제 "리셋 시각부터 다음 리셋 시각까지" 끊김 없이 쌓입니다.** 미국 종목은 서머타임에 맞춰 리셋 시각이 22:30과 23:30 사이에서 자동으로 바뀝니다.

### 무엇이 문제였나요?
1. **자정에 VWAP이 초기화되던 버그.** 미국장은 한국 시간 밤 22:30에 열려 새벽 05:00에 닫힙니다(서머타임 기준). 그런데 봇은 날짜가 바뀌는 **00:00에 VWAP을 처음부터 다시 계산**했습니다. 그래서 장 한가운데에서 VWAP 선·매수/매도 타겟·Dev Band가 갑자기 현재가 쪽으로 튀었습니다.
   예) 23:59 가격 100 → 00:00 가격 106 (거래량 같음): 올바른 VWAP은 **103**이지만 봇은 **106**으로 계산했습니다.
2. **서머타임이 끝나면 리셋 시각이 1시간 어긋나는 문제.** 미국 서머타임은 **2026년 11월 1일(일)** 에 끝납니다. 그 뒤로 미국 정규장은 한국 시간 **23:30**에 열립니다. 리셋이 22:30에 고정돼 있으면 개장 1시간 전(프리마켓)부터 새 세션을 세는 셈이었습니다.
3. **실제로는 최근 2.5시간만 보고 있었던 문제.** 봇은 매번 최근 1분봉 150개(약 2.5시간)만 받아 왔습니다. 그래서 "리셋 시각부터 누적"이라는 설명과 달리, 실제 VWAP은 대부분 "최근 2.5시간 누적"이었습니다.

### 어떻게 바뀌었나요?
| 항목 | 예전 | 지금 |
|---|---|---|
| VWAP이 새로 시작되는 때 | 리셋 시각 **그리고 매일 00:00** | 리셋 시각 **한 번만** |
| 미국 종목 리셋 시각 | 22:30 고정 | 서머타임 중 **22:30**, 서머타임 해제 후 **23:30** (자동) |
| VWAP에 쓰는 봉 | 항상 최근 150개 | **세션 시작부터 지금까지 전부** (최대 1600개) |
| 정규장 밖(프리·애프터·주간거래) 봉 | VWAP에 포함, 매매 가능 | **똑같이 포함, 매매 가능** (바뀌지 않음) |
| 일 손실한도의 "하루" | 리셋 시각 기준 세션 | 같은 세션 기준 (미국 종목은 서머타임 자동 반영) |

- 서머타임 날짜는 미국 규칙(3월 둘째 일요일 ~ 11월 첫째 일요일)으로 봇이 직접 계산합니다.
- 서머타임이 바뀌는 날은 그 세션만 하루가 25시간(11월) 또는 23시간(3월)입니다.

### 사용자가 해야 할 일
- **설정은 바꾸지 않아도 됩니다.** 미국 종목 리셋 시각을 `22:30` 그대로 두면 11월 1일 이후 자동으로 23:30에 리셋됩니다. 11월 1일 전에 S9에 배포되어 있어야 합니다.
- 리셋 시각을 일부러 고정하고 싶다면 22:30/23:30이 아닌 값(예: `21:00`)을 넣으세요. 그 시각을 매일 그대로 씁니다.

### 체감할 수 있는 차이 (꼭 읽어 주세요)
- **VWAP 선이 예전보다 천천히 움직입니다.** 이제 세션 전체(최대 하루치) 거래를 평균하기 때문입니다. 특히 낮 시간(주간거래)이나 새벽(애프터마켓)에는 VWAP이 전날 밤 정규장 가격 쪽에 머무는 경향이 생깁니다.
- 같은 N%/M% 설정이라도 **매수·매도 타겟 위치와 체결 횟수가 예전과 달라질 수 있습니다.** 배포 후 며칠은 가상봇 결과와 판단 사유를 함께 지켜봐 주세요.
- Dev Band(표준편차 밴드)도 세션 전체 기준이라 대체로 폭이 넓어집니다.

### 상태 화면에 추가된 값 (확인용)
- `session_label`: 지금 VWAP 세션 기준과 기간. 예) `미국장 자동(서머타임 22:30 / 표준시 23:30) 10-06 22:30~10-07 22:30 KST`
- `vwap_full_session`: 이번 VWAP이 세션 시작부터의 봉을 모두 포함했으면 `true`입니다. `false`면 시세 서버에서 과거 봉을 다 받지 못해 일부 구간만 누적한 값입니다(예전과 같은 방식이고 매매는 그대로 진행). 이 경우 봇 로그에 `⚠️ VWAP 이 세션 시작(...)부터의 봉을 다 포함하지 못함` 경고가 세션마다 한 번 남습니다.

## 9. "거래 시작 시각" 대기 중에도 손절은 합니다 (2026-10-07, ADR-0009)

### 한 줄 요약
**거래 시작 시각 전에는 "새로 사는 것"만 멈춥니다.** 이미 가지고 있는 주식은 대기 중에도 평소처럼 손절·매도합니다.

### 거래 시작 시각이란?
VWAP 이 새로 시작(리셋)된 직후는 가격이 크게 출렁이고 VWAP 도 몇 개 안 되는 봉으로 계산돼 불안정합니다. 그래서 "리셋 후 조금 기다렸다가 사자"는 설정이 거래 시작 시각입니다.
- 예) 리셋 `22:30`, 거래 시작 `23:30` → 22:30~23:29 는 **대기 구간**, 23:30 부터 정상 매매.
- 비워 두면 대기 없이 리셋 직후부터 바로 매매합니다(현재 운영 설정은 모두 빈 값).

### 무엇이 문제였나요?
예전에는 대기 구간 동안 봇이 **모든 판단을 "대기"로 바꿔 버렸습니다.** 그래서 전날 밤에 사서 들고 있던 주식이 대기 구간에 손절가 아래로 떨어져도 **손절하지 않았고**, 걸어 둔 매도 주문까지 취소했습니다. 대기 구간이 1시간이면 그 1시간 동안 손절 보호가 없었던 것입니다.

### 어떻게 바뀌었나요? (대기 구간 안에서)
| 내 상황 | 예전 | 지금 |
|---|---|---|
| 주식 없음, 가격이 VWAP 아래(평소라면 매수) | 매수 안 함 | 매수 안 함 (같음) |
| 주식 보유, 손절가 아래로 하락 | **손절 안 함**, 미체결 주문 전부 취소 | **즉시 시장가 손절** (평소와 같음) |
| 주식 보유, 가격이 VWAP 위 | 매도 주문도 취소 | **지정가 매도 주문** (평소와 같음) |
| 주식 보유, 그 사이 가격 | 미체결 주문 취소 | 미체결 주문 취소 (평소와 같음) |

- 쉽게 말해 **주식을 갖고 있을 때는 거래 시작 시각 설정이 아무 영향을 주지 않습니다.** 주식이 없을 때만 "아직 사지 말 것"으로 작동합니다.
- 대기 중에 매도하는 주기에는, 혹시 남아 있는 매수 주문(일부만 체결되고 남은 잔량 등)을 먼저 취소합니다. 대기 중에 새로 사게 되는 일을 막기 위해서입니다.
- 일 최대 손실한도(패닉 정지)는 예전과 똑같이 대기와 상관없이 작동합니다.

### 화면에서 보이는 것
- 대기 구간이면 상단에 **"시작 대기"** 표시가 그대로 나옵니다(주식 보유 여부와 관계없이).
- 주식이 없으면 판단 사유가 `WAIT_START_TIME`(거래 시작 시각 이전 → 신규 매수 대기)입니다.
- 주식을 보유 중이면 판단 사유는 평소처럼 `STOP_LOSS`/`SELL_ARMED`/`HOLD` 가 나옵니다.

### 사용자가 해야 할 일
- 없습니다. 현재 설정의 거래 시작 시각은 모두 비어 있어서 배포 후에도 실제 매매에는 당장 차이가 없습니다. 앞으로 거래 시작 시각을 켜더라도 손절 보호가 유지됩니다.
- 리플레이(과거 시뮬레이션)에서 거래 시작 시각을 쓰면, 연구용 백테스트 결과와 "대기 구간 신규 매수"만큼 차이가 날 수 있습니다. 정상입니다.

## 10. 실거래 봇은 "가짜 시세"로 사고팔지 않습니다 (2026-10-07, ADR-0010)

### 한 줄 요약
**실거래(REAL) 봇은 시세가 토스나 야후에서 온 진짜 값일 때만 판단합니다.** 출처를 알 수 없거나 프로그램이 만든 임시 가격(난수)이면, 그 1분 동안은 아무것도 사고팔지 않고 알림만 보냅니다.

### 무엇이 문제였나요?
1. 시세 조회 부품은 "모의 동작" 상태가 되면 화면이 비지 않도록 **아무렇게나 만든 가격(난수 봉)** 을 돌려줄 수 있었습니다. 실제 주가와 전혀 상관없는 숫자입니다. 이 모의 동작이 되는 경우는 두 가지입니다.
   - **토스 API 키를 넣지 않은 경우**: 항상 모의 동작입니다. (키가 없으니 당연한 동작입니다.)
   - **키를 넣은 경우**: 원래는 모의 동작이 될 수 없습니다. 다만 대시보드 새로고침과 봇이 **동시에 토큰(출입증)을 다시 발급받다가 서로 꼬이면**, 토큰은 멀쩡한데도 "모의 동작" 표시가 잘못 남을 수 있었습니다(경합 상태). 드문 일이지만 한 번 걸리면 최대 약 1시간 지속되고, 이때 난수 봉이 나올 수 있었습니다.
   - 즉 "키가 있는데 토스·야후가 둘 다 응답 없음"만으로는 난수 봉이 나오지 않습니다. 그때는 그냥 "시세 없음"으로 처리됩니다.
2. 이 가짜 가격으로 실거래 봇이 판단하면 엉뚱한 일이 생길 수 있습니다. 예) 실제 주가는 250달러인데 가짜 가격이 180달러라면, 봇은 "손절가 아래로 떨어졌다"고 보고 **내 주식을 실제 시장에서 시장가로 팔아 버릴 수 있었습니다.**
3. 더 드문 경우지만 더 위험한 문제도 찾았습니다. 대시보드에서 잔고를 새로고침하는 순간 토큰 발급이 실패하면, 실거래 봇이 한동안(최대 약 1시간) **실제로는 주문을 내지 않으면서 "주문했다"고 착각**할 수 있었습니다. 이때 손절은 실제로 팔리지 않았는데도 "손절 체결"로 실거래 기록에 남을 수 있었습니다. 이번에 이 경로를 막았습니다.

### 어떻게 바뀌었나요?
| 상황 (실거래 봇) | 예전 | 지금 |
|---|---|---|
| 시세가 토스·야후에서 정상으로 옴 | 평소대로 매매 | **평소대로 매매 (같음)** |
| 시세가 가짜(난수)이거나 출처를 모름 | 그 가격으로 매수·매도·손절 판단 | **그 1분은 아무것도 안 함.** 이미 걸어 둔 주문도 취소하지 않고 그대로 둠 |
| 토스 API 키를 넣지 않고 실거래 봇을 켬 | 가짜 잔고로 가짜 주문을 내고 "주문 제출" 알림 | **아무것도 안 함** + 알림 |
| 위 상태가 3분(3주기) 계속됨 | (알림 없음) | **긴급(CRITICAL) 알림** — "손절 판정이 멈춰 있으니 토스 앱에서 직접 확인하세요". 계속되면 **30분마다 다시 알림**(얼마나 지속됐는지, 원인, 마지막으로 확인된 보유 수량 포함) |
| 토큰 발급 실패 | 그 주기 오류 처리(5주기 연속이면 알림) | 같음 |

- **손절도 그 1분 동안은 멈춥니다.** 가짜 가격으로 손절을 판단하면 멀쩡한 주식을 팔 수 있어서 더 위험하기 때문입니다. 대신 3분째에 긴급 알림을 보내 사람이 직접 확인하게 합니다. 이미 걸어 둔 지정가 매도 주문은 거래소에 그대로 남아 있으니, 그 가격에 오면 정상적으로 체결됩니다.
- 일 최대 손실한도(패닉 정지)도 같은 이유로 그 1분 동안은 계산하지 않습니다.
- 진짜 시세가 다시 들어오면 다음 주기부터 자동으로 평소처럼 돌아갑니다. 따로 할 일은 없습니다.
- **가상 봇(가상 1~3)은 바뀌지 않았습니다.** 연습용이라 가짜 가격으로 돌아도 괜찮습니다.

### 화면과 알림에서 보이는 것
- 판단 사유가 **`DATA_UNTRUSTED`**(빨간 배지 "시세 출처 신뢰 불가 · 매매 보류")로 나옵니다. 사유 문장에 이유(난수 봉 / 출처 불명 / 토스 API 키 미설정)와 몇 주기째인지가 나옵니다.
- 이벤트 로그에 `ERROR`(경고 수준, 사유 `DATA_UNTRUSTED`)가 남습니다. 신뢰 불가 구간이 새로 시작될 때마다 반드시 1건 남고, 같은 구간 안에서는 10분에 한 번만 더 기록됩니다. Discord 알림도 구간이 시작될 때마다 옵니다. 다만 신뢰/불가가 10분 안에 여러 번 반복되면 알림이 쏟아지지 않도록 묶어 두었다가, 다음 알림(새 구간 시작·긴급 알림·정상 복귀 요약)에 "생략된 구간 시작 N회"로 함께 알려 줍니다.
- 3주기 연속이면 `CRITICAL` 이벤트와 Discord 알림이 옵니다. 그 뒤에도 신뢰 불가가 계속되면 30분마다 다시 알립니다. 알림에는 지속 시간, 원인, 마지막으로 확인된 보유 수량이 적힙니다. 신뢰 시세가 한 번 돌아오면 다음 구간은 처음부터 다시 셉니다.

### 사용자가 해야 할 일
- **`DATA_UNTRUSTED` 알림을 받으면**: 사유 문장에 "토스 API 키 미설정"이 있으면 설정에서 키를 넣으세요. 그 밖의 경우에는 인터넷이나 시세 서버 장애일 가능성이 큽니다. **주식을 들고 있다면 토스 앱에서 가격을 직접 확인하고, 필요하면 직접 손절하세요.**
- 평소(키 정상, 시세 정상)에는 차이가 없습니다.

## 11. 3단계: 리플레이 · 섀도우 · 봉 데이터 적재 사용법 (2026-10-07)

3단계는 "전략이 실제로 쓸 만한가"를 **숫자로 확인**하기 위한 도구 모음입니다. 실거래 매매 동작은 바뀌지 않습니다. 대시보드에 **▶️ 리플레이** 탭과 **🔍 섀도우** 탭이 추가되었습니다.

### 11-1. 리플레이 탭 (과거에 돌려 보기)

**한 줄 요약**: 지금 실거래에 쓰는 설정 그대로 과거 봉 위에서 가상으로 매매해 보고, 비용을 뺀 성과를 알려 줍니다. (주문은 전혀 나가지 않습니다.)

**실행 방법**
1. "기간 (최근 N일)"을 고릅니다.
2. **"현재 실거래 설정으로 리플레이"** 버튼 하나만 누르면 됩니다. 종목·N%/M%·손절 등은 실거래 설정을 자동으로 가져옵니다.
3. 진행 막대가 끝나면 결과가 나옵니다. 계산 중에도 대시보드와 봇은 정상 동작합니다.

**기간 규칙**
- 기간은 **달력일** 기준입니다(영업일이 아닙니다).
- 1분봉은 **최대 30일**, 5분·15분봉은 **최대 60일**입니다. 더 길게 요청하면 서버가 잘라내고, "데이터·가정"의 경고에 그 사실을 적어 줍니다.

**결과 화면 읽는 법 (위에서 아래로)**
| 항목 | 뜻 |
|---|---|
| 판정 배너 | 거래 30건 미만이면 **판단 불가**(기간을 늘려 보세요). 충분하면 비용 반영 후 기대값이 **음(-)** / **불확실** / **양(+) 가능성** 중 하나로 나옵니다. 양(+)이어도 과거 시뮬레이션일 뿐 미래를 보장하지 않습니다. |
| KPI 카드 | 순손익(수수료·슬리피지 반영 후), 수익률, 기대값/거래(한 번 거래할 때 평균적으로 남는 %), 승률, 거래수, t-stat(우연이 아닐 가능성의 척도, ±2 근처가 판정 경계) 등 |
| MDD (최대 낙폭) | 손익곡선이 **고점에서 가장 많이 빠진 폭**입니다. 클수록 중간에 버티기 힘든 전략입니다. |
| Buy&Hold 비교 | "그냥 처음에 사서 계속 들고 있었다면"의 수익률과, **전략 − Buy&Hold** 차이(%p)입니다. 전략이 이 값을 못 이기면 매매할 이유가 약합니다. |
| 손익곡선 | 파란 실선이 전략, 주황 점선이 Buy & Hold입니다. |
| 청산 사유 3종 | **지정가 매도**(목표가에 걸어 둔 매도가 체결) / **시장가 손절**(손절가 이탈로 즉시 청산) / **데이터 끝 정리**(기간이 끝날 때 아직 들고 있어서 마지막 봉에서 강제로 정리, 실제 매도 신호가 아님) — 사유별 건수와 평균·합계 수익률 표가 나옵니다. |
| 거래 목록 | 최신순, 최대 500건까지 표시합니다. |

**"데이터 · 가정" 패널 (결과 해석 전에 꼭 읽으세요)**
- **기간 / 세션 수 / 봉 개수 / 주기**: 실제로 쓴 데이터의 범위입니다.
- **데이터 출처**: "적재분"(우리 봇이 직접 쌓아 둔 봉, 11-3)과 "Yahoo"(부족분을 보충한 봉)의 개수입니다.
- **부분 적재 가능 세션**: 봇이 꺼져 있었거나 점검 중이어서 **봉이 일부 빠졌을 수 있는 날**입니다. 그 날의 결과는 실제와 다를 수 있으니 목록의 날짜를 눈여겨보세요. "없음"이면 이상 없다는 뜻입니다.
- **데이터 한계**: 이 데이터로는 알 수 없는 것(예: 야후 과거 봉 제공 기간의 한계)을 적어 둡니다.
- **모델링하지 않은 것**: 아래 "한계" 참고.
- **경고**: 기간이 잘렸다, 데이터가 모자란다 등 주의 사항입니다.

**고급 설정 (접혀 있음, 기본값이면 충분)**
- **왕복 수수료(%)**: 매수+매도 한 번에 드는 수수료. 기본 0.20.
- **왕복 슬리피지(%)**: 주문가와 실제 체결가의 불리한 차이를 가정하는 값. 기본 0.05.
- **지정가 체결 버퍼(%)**: 지정가에 "가격이 닿기만" 하면 체결되었다고 보는 것은 낙관적이므로, **조금 더 지나가야 체결**되었다고 보수적으로 가정하는 값. 기본 0.00(닿으면 체결).
- 수수료·슬리피지를 올리거나 버퍼를 키울수록 결과가 현실적(보수적)이 됩니다. 결과가 "양(+)"으로 나와도 이 값을 올려 다시 돌려 보면 버티는지 확인할 수 있습니다.

**한계 (백테스트가 다루지 않는 것)** — 결과를 볼 때 이 항목들 때문에 실제 성과가 달라질 수 있음을 기억하세요.
1. **일 손실한도 패닉**: 실거래에서는 하루 손실이 한도를 넘으면 전량 청산 후 정지하지만, 리플레이에서는 이 기능이 동작하지 않습니다.
2. **부분체결/호가 대기열**: 지정가가 "일부만 체결되거나, 앞사람 때문에 내 차례가 늦는" 일을 모사하지 않습니다.
3. **취소·정정 지연**: 주문을 취소·정정하는 데 걸리는 시간이 없다고 가정합니다.
4. **시간외 거래 여부 차이(Yahoo vs Toss)**: 야후 봉과 토스 봉이 시간외(프리·애프터) 구간을 다르게 줄 수 있습니다.
5. **지표 계산 창 차이(150봉 vs 전체)**: RSI·ADX 같은 지표를 실거래 봇과 다른 길이의 봉으로 계산할 수 있어 신호가 조금 다를 수 있습니다.
6. **거래 시작 대기 판단 시각 = 봉 마감 시각**: 거래 시작 시각 전후의 판단 시점이 실거래와 약간 다를 수 있습니다.
7. **예산: 고정 명목금액**: 매번 같은 금액으로 사는 것으로 계산하며, 현금이 모자라도 수량을 줄이지 않습니다.

> 이 때문에 리플레이는 "이 전략이 대체로 통했는가"를 보는 **연구용 도구**이지, 미래 수익을 알려 주는 도구가 아닙니다. 판단 불가·불확실이면 결론을 내리지 말고 기간을 늘려 다시 보세요.

### 11-2. 섀도우 탭 (실거래와 가상 원장 비교)

**무엇인가요?** 실거래(REAL) 봇이 한 주기를 돌 때마다, **같은 봉·같은 설정으로 "가상 장부"가 똑같이 한 번 더 판단**합니다(진짜 주문은 나가지 않습니다). 두 결과를 나란히 놓으면, 전략 자체의 문제가 아니라 **실제 체결 과정에서 생기는 차이**(체결가 차이, 미체결, 슬리피지, 시장 사정 등)가 드러납니다.

**동작 조건**
- **REAL 봇이 실행 중일 때만** 동작합니다. 실거래 봇이 멈춰 있으면 섀도우도 멈추고, 상단에 "섀도우는 REAL 실행 중에만 동작합니다"가 나옵니다.
- 설정 **`shadow_enabled`**(기본 켬)로 켜고 끕니다. 끄면 "섀도우가 꺼져 있습니다"라고 표시됩니다.
- 비교 수수료 가정은 `shadow_fee_roundtrip_pct`(기본 0.2%), 일치로 볼 가격 차이 허용치는 `shadow_price_tolerance_pct`(기본 0.05%)입니다.
- 섀도우가 REAL의 매매에 영향을 주는 일은 없습니다(예외가 나도 REAL은 그대로 진행).

**비교 판정 7종** (같은 주기의 같은 종류 주문끼리 짝지어 판정합니다)
| 판정 | 뜻 |
|---|---|
| 일치 | 양쪽 모두 체결됐고 체결가 차이가 허용치(0.05%) 이내 |
| 체결가 차이 | 양쪽 모두 체결됐지만 가격 차이가 허용치를 넘음 |
| 실거래만 미체결 | 섀도우는 체결됐는데 실거래는 안 됨 (실제 호가 사정으로 못 산/판 경우) |
| 섀도우만 미체결 | 실거래는 체결됐는데 섀도우는 안 됨 (실거래가 더 유리하게 체결된 경우) |
| 둘 다 미체결 | 양쪽 모두 주문만 내고 체결 안 됨 (괴리가 아니라서 목록에서는 숨김) |
| 실거래만 주문 | 실거래는 주문을 냈는데 섀도우는 같은 주기에 주문이 없음 → **판단이 갈린 경우**, 원인을 확인할 가치가 큼 |
| 섀도우만 주문 | 반대로 섀도우만 주문을 냄 → 마찬가지로 판단이 갈린 경우 |

**숫자의 뜻**
- **일치율**: `일치 ÷ (일치 + 체결가 차이)`, 즉 **양쪽 모두 체결된 쌍 중** 가격이 같다고 볼 수 있는 비율입니다. 높을수록 실제 체결이 가상 모델과 비슷하다는 뜻입니다.
- **순손익**: 손익에서 수수료를 뺀 값. 실거래는 실제 수수료 기록을, 섀도우는 청산 금액 × 추정 수수료율을 씁니다.
- **거래수 / 승률**: **청산 결정** 단위로 셉니다. 같은 주기·같은 방향의 청산이 시장가 재시도 때문에 여러 번 나뉘어 체결돼도 **1건**이고(예: 시장가 재시도 3건 + 지정가 매도 1건 = 거래수 2), 승률도 이 건수를 분모로, 한 결정의 손익 합이 0보다 크면 승리로 셉니다. 전체 체결 건수는 **체결수**로 따로 나옵니다. 순손익은 어차피 합계라 영향이 없습니다.
- **순손익 차이 (섀도우 − 실거래)**: 양수면 "가상 장부가 더 벌었다 = 실제 실행이 이상적인 모델보다 손해를 봤다", 음수면 반대입니다. 이 값이 계속 크게 한쪽으로 쏠리면 **실행 괴리**가 있다는 신호입니다.
- "ⓘ 용어 설명"을 열면 거래수/체결수/가격차 등의 정의가 화면에 그대로 나옵니다. 비교 기간은 1일·7일·30일 중 고를 수 있습니다.

**"건너뜀"이란? (마지막 건너뜀 안내)** 섀도우가 일부러 그 주기를 쉬었다는 표시입니다. 오류가 아니라 **안전장치**인 경우가 대부분입니다.
| 표시 | 쉬운 설명 |
|---|---|
| 섀도우 비활성화 | 설정으로 꺼 둠 |
| REAL 봇 정지 중 | 실거래 봇이 멈춘 주기(수동 정지·손실한도 정지 포함) |
| REAL 데이터 신뢰 불가 / REAL 루프 오류 | 실거래 봇이 그 주기에 시세를 못 믿거나 오류가 나서 판단을 보류했으므로 섀도우도 같이 쉼 (10장 참고) |
| 봉 데이터 없음 / 봉 데이터 신뢰 불가 | 판단에 쓸 봉이 없거나 출처를 믿을 수 없음 |
| 기준 자본 없음 | 종목이나 기준 자본금(`real_initial_balance`)이 설정되지 않음 |
| 기준 시각 없음 | 실거래의 판단 시각을 알 수 없어 같은 시각으로 맞출 수 없음 |
| 섀도우 일 손실한도 정지 | 섀도우 자체의 일 최대 손실한도를 넘어 이번 세션은 쉼 (다음 세션에 재개) |
| 보유 상태 확인 불가 | 실거래 보유 조회에 실패해 동기화를 다음 주기로 미룸 |
| 브로커 교체 감지 | 섀도우의 시세·가상 장부 연결이 바뀐 것을 발견해 **보호 차원에서 폐기** (다음 주기에 새로 시작) |
| 내부 예외 발생 | 섀도우 내부 오류. 실거래에는 영향 없음, 반복되면 개발자에게 알려 주세요 |

**"재동기화"란? (마지막 동기화 · 사유)** 섀도우의 가상 장부를 **실거래의 실제 보유 수량·평단가**에 맞춰 다시 세팅하는 것입니다(그래야 같은 출발선에서 비교됩니다). 이때 미체결 가상 주문은 비웁니다.
| 사유 | 언제 |
|---|---|
| 최초 동기화 | 섀도우를 처음 시작할 때 |
| 봇 시작 | 실거래 봇을 (재)시작했거나 서버가 재시작됐을 때 |
| 세션 시작 | 새 VWAP 세션이 시작될 때 (8장) |
| 설정 변경 | 종목이나 기준 자본금이 바뀌었을 때 |
| 섀도우 재활성화 | `shadow_enabled`를 껐다가 다시 켰을 때 |

**표시되는 특별한 문구**
- **"REAL 손실한도 정지(비교 제외)"**: 실거래가 일 최대 손실한도로 패닉 청산을 한 주문입니다. 섀도우는 이 주기를 일부러 쉬므로 짝이 없는 것이 당연합니다. "실거래만 주문"으로 세면 오해를 부르기 때문에 **판정 건수에서 빼고 흐리게** 따로 표시합니다.
- **"3단계 이전/앱 주문 N건은 비교 제외"**: 3단계 도입 전의 거래 기록이나, 토스 앱에서 직접 낸 주문에는 "어느 주기에 낸 주문인지"를 알려 주는 번호(`cycle_id`)가 없어서 섀도우와 짝지을 수 없습니다. 그래서 비교와 요약 숫자에 **포함하지 않습니다**(고장이 아닙니다).
- **"섀도우 현금이 음수입니다 (과배분)"**: 섀도우 현금은 `기준 자본금 − 실거래 보유 원가`로 맞춥니다. 실거래가 기준 자본금보다 큰 금액을 이미 보유 중이면(예: 앱에서 직접 더 샀거나 자본금 설정을 낮춘 경우) 현금이 마이너스가 됩니다. **이상 상태가 아니라 안내**입니다. 보유 중에는 어차피 새로 사지 않으므로 실거래와 판단이 같고, 청산하고 나면 정상으로 돌아옵니다. 다만 그 사이 섀도우는 신규 매수를 하지 못합니다.

### 11-3. 가상봇 V1~V3 숨김 토글 (헤더의 "고급")

- 헤더(탭 줄)의 **"고급: 가상봇 V1~V3 표시"** 체크박스입니다.
- 체크를 끄면(기본) 가상봇 V1~V3와 관련된 탭(가상 자동매매, 과거 백테스트)·카드가 **화면에서 숨겨져** 실거래·리플레이·섀도우 중심으로 간결하게 보입니다. 켜면 다시 나타납니다.
- 설정은 **기기(브라우저)별로 저장**됩니다. 휴대폰에서 켜도 PC에서는 따로 설정해야 합니다.
- 화면에서 숨기는 것뿐이며, 가상봇 동작·기록은 그대로입니다.

### 11-4. 봉 데이터 적재 (리플레이의 원재료)

- **봇이 실행 중일 때** 마감된 봉이 S9의 `data/bars` 폴더에 자동으로 쌓입니다(설정 `bars_store_enabled`, 기본 켬).
- 이 데이터가 **리플레이**와 이후 **4단계(전략 재연구)** 의 원재료가 됩니다. 봇이 오래 켜져 있을수록 리플레이가 야후 보충분 없이 우리 데이터로 돌아가 더 믿을 만해집니다.
- 봇이 꺼져 있던 구간은 비어 있을 수 있고, 그 구간은 리플레이 결과의 "부분 적재 가능 세션"에 표시됩니다(11-1).

### 사용자가 해야 할 일
- 필수 조치는 없습니다. 설정을 바꾸지 않아도 3단계 기능이 기본값으로 동작합니다.
- 배포 후 며칠 동안 섀도우 탭에서 **일치율**과 **순손익 차이**를 가끔 확인하고, "실거래만 주문 / 섀도우만 주문"이 반복되면 알려 주세요.
- 리플레이는 결과가 "판단 불가"이면 기간을 늘리고, "양(+)"이어도 고급 설정에서 수수료·슬리피지를 올려 다시 돌려 보세요.
